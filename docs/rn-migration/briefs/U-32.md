## Shape

- One model file per Swift model (`diaryDayModel.ts`, `foodSearchModel.ts`, and a small model per
  sheet), each with constructor injection: the repositories it uses (as functions or objects), a
  `subscribe(listener)` that re-reads after every local write and sync run, `now`. Jest builds them
  with test doubles.
- **Writes.** A food added, edited or deleted goes through
  `getDataEnvironment().diaryEntries` (`recordUpserts`, `recordTombstone`), then
  `notifyLocalMutation()`. A delete also removes the detail row, as `DiaryDayModel.delete` does.
  Water, exercise and weight go through `tracking` and are local-only (I4): call
  `notifyLocalMutation()` after them too, so Today re-reads.
- **Food search (DY-03).** Local, as `FoodSearchModel.swift`: `catalog.recentFoods(limit: 5)`,
  `catalog.searchFoods(query)`, `catalog.customFoods()`, and the create-custom-food row. The old
  app calls no backend here; if you find a call, report it, do not add an API client.
- **Custom food (DY-04).** Per-100g or per-serving basis with the clamps of the Swift sheet; saved
  through `catalog.saveCustomFood`.
- **Manual log (DY-05).** An amount input; kcal is always derived from the food row and is never
  typed (a test).
- **Exercise (DY-06).** Type, a 5-minute stepper, optional burned kcal. The sheet clamps duration to
  0 to 600 minutes and kcal to 0 to 5000; the repository clamps again (that is known).
- **Water (DY-07).** Droplet ring, plus and minus tiles of 250 ml, goal from targets (default 8),
  day total never below 0.
- **ED-safe (I7).** No `edSafe` call in `features/diary`: the components own the policy.
- **Identifiers.** Every `accessibilityIdentifier` of the Swift diary views becomes the `testID` of
  the same element (same string): `addfood.*`, `diary.*`, `custom.*`, `manual.*`, `exercise.*`, the
  stepper and the water identifiers.
  `grep -rhoE 'accessibilityIdentifier\("[^"]+"\)' native/App/Features/Diary` lists them; put the
  table in `parity-detail/diary.md`.
- **Route.** `src/app/diary.tsx` default-exports the day sheet (it is opened as a sheet from Today
  and through `coachcal://diary`) and nothing else: no tests under `src/app`. The other sheets are
  components of the feature, not routes.
