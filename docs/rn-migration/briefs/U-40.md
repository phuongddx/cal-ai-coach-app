## Shape

- One model file per Swift flow (`progressModel.ts`, `coachModel.ts`, a small model per sheet), each
  with constructor injection: the repositories it uses, `ownerId`, `now`, the database handle for
  the day totals. Jest builds them with test doubles; the tests that need the tables use a fresh
  `sql.js` database per test, the way your diary twin did.
- **Owner id.** The user of the session when one exists (`getSessionStore().getSession()?.user.id`),
  otherwise `DEMO_USER_ID` from `apps/mobile/src/data/repos/seedDataManager.ts`; the route file
  passes it.
- **Charts (PG-02, PG-03).** Drawn with `react-native-svg` (installed). The accessibility
  description is built from the series exactly as `ChartDescriptorTests` describes: port the test
  first. Weekly energy is seven bars with value labels and the average footer.
- **ED-safe (I7).** Weekly energy is hidden entirely in ED-safe mode. The feature holds no policy
  branch: wrap the chart in `EdSafeCollapse` from `src/design`, which owns it. No `edSafe` call
  under `features/progress` or `features/coach`.
- **Weight log (PG-02).** A sheet over the tracking repository (`weights`, `addWeight`), local-only.
- **Achievements (PG-04).** The streak hero with the freeze chip, earned and locked badges from the
  engagement repository, and the disabled progress-photos row with the same copy.
- **Coach (CH-01).** The weekly review card and the insights: local rules only, as the Swift flow;
  no network call.
- **Identifiers.** Every `accessibilityIdentifier` of the Swift views becomes the `testID` of the
  same element (same string). Put the table in `parity-detail/progress-coach.md`.
- **Route.** `(tabs)/progress.tsx` and `(tabs)/coach.tsx` default-export the screens and nothing
  else: no tests under `src/app`. They are the only files of the feature that import
  `getDataEnvironment`, `getSessionStore` and `notifyLocalMutation`.
