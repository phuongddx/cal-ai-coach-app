## Goal

The app opens the way the Swift app does. The session and the stored flags load before the first
screen. The root gate shows sign-in, onboarding or the tabbed shell by the rules of `RootView.swift`.
Sign-out and account deletion reset the local data as `AppEnvironment.swift` does. Every screen can
take its dependencies from one React environment. The debug console sets the flags at runtime.

## Shape

- **Modules live outside `src/app`.** Expo Router makes every file under `src/app` a route, so the
  rule and the reset go under `src/platform/` as pure modules with injected dependencies.
- **Root gate.** `src/platform/rootGate.ts` exports a pure function that maps a state to
  `wait | sign-in | onboarding | shell`, with the rules of `RootView.swift`: not ready, then wait;
  sign-in required and no session, then sign-in; a target exists or onboarding is pending, then the
  shell; otherwise onboarding. `requiresSignIn` is `getDebugFlags().requireSignIn`; "a target
  exists" is `getDataEnvironment().targets.activeTarget()` (read how Swift sets
  `onboardingPending` and port that rule). `src/app/_layout.tsx` runs the launch sequence, then
  renders the gate with typed routes.
- **Launch sequence.** Load the session (`getSessionStore().load()`), read the stored ED-safe mode,
  start the sync triggers (`getSyncRuntime()` then `startTriggers()`), start the data binding, then
  decide the gate. Nothing native runs at import time.
- **ED-safe persistence (the launch half).** Swift keeps `edSafeMode` in `UserDefaults` under the key
  `edSafeMode` and `--ccEDSafe` forces it on. RN keeps it in the `app_settings` table under the same
  key with the value `'1'` or `'0'`, through `readAppSetting` and `writeAppSetting`
  (`apps/mobile/src/data/repos/engagementRepository.ts`) over `getDataEnvironment().db`. At launch
  call `setEdSafeMode(flags.edSafe || stored)`. The settings toggle and the write are U-41's: it
  writes the same key; do not change that key.
- **Account reset.** `src/platform/accountReset.ts` ports what `AppEnvironment.swift` does on
  sign-out and on account deletion (read the function that removes the `edSafeMode` and HealthKit
  keys, around lines 300 to 340): local rows through the sync store's `reset()`, the stored flags,
  the session. Injected dependencies, so Jest proves each step and their order.
- **React environment.** `src/app/environment.tsx` exports `AppEnvironmentProvider` and
  `useAppEnvironment()`: the data environment, the session store, the API client factory, the clock,
  the flags, the telemetry seam, `openScan()`, `resetLocalData()`. The feature route files keep
  their own wiring in this wave; moving them onto the provider is a later unit.
- **Debug console (PL-05).** `src/app/debug.tsx` gets a Flags card with one switch per flag of
  `getDebugFlags()` (through `setDebugFlags`) and one for ED-safe mode (through `setEdSafeMode`).
  The existing cards keep working. Reading process arguments needs a native module and the native
  slot: not in this unit; say so in the findings.
- **Launch arguments.** `apps/mobile/src/debug/launchArgs.ts` holds a provisional parser. Make
  `flagsFromArguments` agree with `DebugLaunchArguments.parse()` in `AppEnvironment.swift` (lines
  50 to 110): the names, which arguments take a value and in what form. Keep the exports
  `getDebugFlags`, `setDebugFlags`, `getDebugFlags` callers rely on: U-30, U-31 and U-32 import
  them.
- **Telemetry seam (PL-02, I8).** `src/platform/telemetry/telemetry.ts`: `createTelemetry()` with
  `track(name, payload)`, an allow-list of event names and a scrub step that drops photo, health and
  calorie text, ported from the Sentry and PostHog setup in `AppEnvironment.swift`. No SDK is
  imported in this unit (U-50 adds them with the native slot); nothing leaves the device.
