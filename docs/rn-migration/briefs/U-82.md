## Goal

After this pull request merges, a merge takes its verdict from GitHub Actions:

1. **The integration job.** In `rn-ci.yml`, a job on `ubuntu-24.04` next to `test`, with a
   `postgres:17` service (with its health checks). It does what `gate-integrate.sh` does after
   `start-api`: the API suites against the database, `smoke-scan.sh`, `smoke-auth.sh`,
   `e2e-sync.sh`. It fails when any line of the output holds `[sql-skip]`. It needs no secret: the
   API is started with the environment the scripts build for a local run (read
   `scripts/rn/start-api.sh` and `scripts/rn/api-env-file.sh`; a value that does not exist on a
   runner is generated in the job, never copied from a machine).
2. **The iOS workflow.** A new file `.github/workflows/rn-ios.yml` on `macos-26`:
   `npm ci`; `npx expo prebuild --platform ios` in `apps/mobile`; build the app for the Simulator;
   boot a Simulator; install the app; start Metro and wait until it serves the bundle; install
   Maestro; run the flows; upload the screenshots and the Maestro report as artifacts. Triggers:
   `pull_request` on `main` and `workflow_dispatch`. A `concurrency` group that cancels the run of
   an older push on the same pull request. A timeout that fits a cold runner.
3. **The Maestro flows**, under `.maestro/`. At least:
   - a fresh install shows onboarding (the title and the button "Get started"), then
     `coachcal://debug?action=seed` brings the seeded Today;
   - the four tabs of the shell;
   - the scan: launch with the scenario fixture, reach the review, tap `+` three times on the first
     item, and assert the kcal of the review changed from 464 to the sum the grams give; every step
     addresses a `scan.*` identifier, never a pixel;
   - a launch with `--ccEDSafe` shows no calorie number on Today.
   Maestro's `launchApp` takes `arguments`; the deep link is `openLink`. Take each step from the
   shell flows of this machine, which already encode the way in.
4. **The Swift workflow runs only for its own files.** `ci.yml` gets path filters: `push` and
   `pull_request` only for `native/**` and for the workflow file itself; `workflow_dispatch` stays.
   The owner may have done this one before you start: if `ci.yml` on `main` already has the filters
   when you read it, leave the file and say so in the findings.

## Tests and proof

- The proof of this unit is the run of GitHub on your own pull request: the `integration` job
  green, and the `rn-ios.yml` run green with its artifacts. Push, open the pull request, and read
  the runs with `gh run list` and `gh run view <id> --log-failed`. Iterate until both are green.
  Quote the URLs of the green runs in the report.
- A job that cannot be made green inside the timebox is reported with its failing log lines and
  the cause, not hidden behind `continue-on-error`.
- The three root gates (`npm test`, `npm run typecheck`, `npm run parity:check`) are green on the
  pushed head. On this machine they print `[sql-skip]`: that is green here (rule 17).
