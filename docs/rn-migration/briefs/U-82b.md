## Why

Six units of evidence wait for one Simulator on the machine of Phương, about four hours each. Zed
decided on 2026-11-28: the CI runs on GitHub-hosted runners; the machine captures Simulator
evidence only when it is really needed, one Simulator at a time, and never a gate in parallel with
a capture. The repository is public, so a macOS runner costs nothing. PR 58 shows that a runner
builds the app for the Simulator, boots one and drives it. This unit makes
`scripts/rn/evidence/run-all.sh` run on a runner, so that an evidence unit captures its rows on
GitHub while other units capture theirs elsewhere. U-83 (a second Simulator on the machine) is
dropped: this unit replaces it.

## You hold no Simulator on this machine, no Metro port, no native build, no API slot

## What to build

1. **The workflow** `.github/workflows/rn-evidence.yml`, `workflow_dispatch` only, with one input,
   `flows` (a string of flow names without `.sh`, empty for every flow). Runs on `macos-26`.
   - Checkout, Xcode, Node and `npm ci` as in `rn-ios.yml`.
   - `expo prebuild`, then the Debug build for the Simulator as in `rn-ios.yml`, with the build
     folder cached (`actions/cache`): the key is the hash of everything the native build reads
     (`package-lock.json`, `apps/mobile/package.json`, `apps/mobile/app.config.ts`,
     `apps/mobile/modules/**`, the patches and plugins the app config names). The step prints
     whether the cache was a hit and how long the build took.
   - A device: the one named `iPhone 17 Pro` on the newest iOS runtime the image has (the frames
     and the screenshots of the machine are drawn on that device). If the image has none, stop
     before the flows and report the list of its devices: the owner decides. `SIM_UDID` carries it.
   - `brew install axe` (the harness drives the app with `axe`; the machine has 2.1.1 from Homebrew).
     Print the version.
   - Metro on 8081, `scripts/rn/ci/wait-metro.sh`, then
     `FLOWS="$flows" COACHCAL_APP_PATH=<the built CoachCal.app> SIM_UDID=<udid> METRO_PORT=8081
     COACHCAL_LOG_DIR="$RUNNER_TEMP/rn-logs" bash scripts/rn/evidence/run-all.sh`. The exit code is
     the number of failed expectations: the step fails when it is not 0, AFTER the artifact is
     uploaded.
   - The artifact `rn-evidence-<run id>`: every file under `docs/rn-migration/evidence/` the run
     created or changed (`git status --porcelain -- docs/rn-migration/evidence`, tracked and
     untracked), `docs/rn-migration/evidence/transcripts/**`, the Metro log. Uploaded always
     (`if: always()`), also when a flow fails or the run stops.
   - `concurrency`: a group per ref, so that two units on two branches run at once and a newer run
     on the same branch cancels the older one. `timeout-minutes: 60`.
2. **Two variables in `lib.sh`, nothing else.** The log directory comes from `COACHCAL_LOG_DIR`
   (default: the path of today), and the URL of the development client is built from `METRO_PORT`.
   A run with neither variable set behaves as today.
3. **The recipe in the findings**: `docs/rn-migration/findings/U-82b.md` holds the three commands
   of an evidence unit: trigger on its branch (`gh workflow run rn-evidence.yml --ref <branch> -f
   flows=<names>`), wait and read the result (`gh run list --workflow rn-evidence.yml --branch
   <branch>`, `gh run view <id> --log-failed`), download the artifact into its worktree (`gh run
   download <id> -n rn-evidence-<id> -D <dir>`).
