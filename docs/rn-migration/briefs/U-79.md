## Goal

The nine `--cc*` arguments work on a device the way they did in the SwiftUI app: passed on the
command line when the app launches, read once at startup. Until now the flags could only be set
from Jest or from the debug console. The evidence units of the Ember phase need them, above all
`--ccEDSafe`, `--ccFixedClock` and `--ccScanScenario`.

## Shape

- **The module** lives under `apps/mobile/modules/` and reads the process arguments of the app.
  Read how a local Expo module is written and autolinked on this SDK in
  `node_modules/expo-modules-core` (the Swift and TypeScript sources and the typings) before you
  write it; `docs/rn-migration/spike/build-recipe.md` says what the spike learned about the tool
  chain. A synchronous function is best; an asynchronous one is acceptable because the launch
  sequence already awaits its steps.
- **One reader.** `apps/mobile/src/debug/launchArgs.ts` gains `loadLaunchArguments()` that asks the
  module and returns an empty list when the module is missing (Jest, an old build), so nothing
  crashes on a build that predates it. The launch sequence calls it once, before the stored flags
  are read, and merges the result with `flagsFromArguments`: an argument wins over a flag set
  earlier in the same launch, the stored ED-safe mode still applies when the argument is absent,
  and `--ccEDSafe` still forces the mode on.
- **The dev switch goes.** Remove `coachcal://?edSafe=1` from the Today route once the argument
  works. Its test goes with it.
- **Harness.** `app_open` in `scripts/rn/evidence/lib.sh` takes optional launch arguments and
  passes them to `xcrun simctl launch`. A flow can then open the app with `--ccEDSafe`.
- **The build.** The module is native code: the development client has to be rebuilt. Build in
  the native worktree as you did in U-33 (`npm ci` there, `bash scripts/rn/native-slot.sh prepare`,
  the build, the compliance check, copy the app to `apps/mobile/build-output/CoachCal-dev.app`,
  `bash scripts/rn/native-slot.sh release`). `df -h /System/Volumes/Data` first: under 8 GB free,
  stop and report. The scan step of the dev client fails when the machine load is above 25: if the
  first build fails there, rerun it once, as in U-33.
- Nothing of the flags' names or values changes: the parser of U-51 already agrees with
  `DebugLaunchArguments.parse()`.
