## Goal

A new user goes through the nine onboarding steps of the old app with the same order, the same
locked copy and the same clamps, ends with a saved target computed by `TargetsEngine`, and grants
HealthKit access exactly once, on the privacy step.

## Shape

- `features/onboarding/onboardingModel.ts`: the step list as a typed array in the model's file, in
  the order of `OnboardingModel.Step`: `valueHero`, `goal`, `bodyMetrics`, `goalWeightPace`,
  `activityDiet`, `projection`, `privacyHealth`, `generating`, `planReveal`. The draft is the
  engine's `QuizProfile`; every number the user can change goes through `TargetsEngine` (pace,
  reveal kcal, macros) and clamps instead of throwing.
- Constructor injection: the model takes `saveTarget`, `readSetting`/`writeSetting`, the HealthKit
  request `() => Promise<'granted' | 'denied'>`, `now`, and `{ disableAnimations }`. Jest builds it
  with test doubles.
- **Locked copy.** Every string is copied verbatim from the Swift view it belongs to, including the
  under-18 footnote, the safety-floor banner and the ED-safe line of the value hero.
- **Projection (OB-10).** Kilograms and weeks only. A test keeps every calorie unit out of the
  screen's strings.
- **Privacy and Health (OB-03).** The button runs the injected request. Granted advances silently;
  denied shows the footnote and lets the user continue. The real request is a function in
  `features/onboarding/healthAccess.ts` that calls `@kingstinct/react-native-healthkit`
  (`requestAuthorization`, read its typings in `node_modules` first); Jest uses the mock.
- **Generating plan (OB-08).** An animated ring and the 4-step checklist with the minimum window of
  the Swift view; with `disableAnimations` the steps flip instantly. The flag comes from
  `getDebugFlags()` in the route file; the model receives it.
- **Finish.** `persistAndFinish` saves the targets through `getDataEnvironment().targets.saveTarget`
  (already through `TargetsEngine` on your side), writes the setting the Swift model writes, calls
  `notifyLocalMutation()` (`apps/mobile/src/data/sync/runtime.ts`) and navigates to the Today tab
  with the typed route. The root gate that skips onboarding next time is U-51: name the setting key
  in the findings so that unit reads the same key.
- **ED-safe (I7).** No `edSafe` call in `features/onboarding`: the components own the policy.
- **Identifiers.** Every `accessibilityIdentifier("onboarding.…")` of the Swift views becomes the
  `testID` of the same element (same string). `grep -rhoE 'accessibilityIdentifier\("[^"]+"\)'
  native/App/Features/Onboarding` lists them; put the table in `parity-detail/onboarding.md`.
- **Route.** `src/app/onboarding/index.tsx` default-exports the flow and nothing else: no tests
  under `src/app`.

## Method

   identifiers.
