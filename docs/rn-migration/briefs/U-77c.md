## Goal

Sign-in follows its real frames end to end, with the behavior it has today.

## Decisions already made

**The behavior does not change.** `requestCode(email)` runs once per tap on "Send code" or
"Resend code"; `verifyCode(email, code)` runs on "Verify"; nothing submits on its own when the
sixth digit lands; `onSignedIn` runs once with the stored session.

**The e-mail step (frames 108 and 109).**
- Back glass button (`auth.emailBack`), title "Continue with email", subtitle "We'll email you a
  6-digit code. If you're new, the same code creates your account."
- The e-mail field on `FillField` with `variant="text"` and its keyboard props (`autoCapitalize`,
  `autoCorrect`, `keyboardType`, `textContentType`, `autoComplete`): `auth.emailField`,
  `auth.emailField.label`, placeholder "Email", the focus ring of the component.
- The dock: "Send code" (`auth.sendCode`), disabled while the address is empty or the form is busy.

**The code step (frames 112 and 113).**
- Back (`auth.emailBack`) and "Use a different email" (`auth.useDifferentEmail`) both return to
  the e-mail step and keep the typed address.
- Title "Enter the code"; "We sent a 6-digit code to **address**." (`auth.codeSent`, the address in
  bold); six cells from `CodeField` (`auth.codeCells`), the hidden input under `auth.otpField`
  with its label "6-digit code"; "Can't find it? Look in Junk or Promotions."
- The dock: "Verify" (`auth.verifyCode`), enabled at six digits and not busy; "Resend code in m:ss"
  (`auth.resendCode`) counts down from 60 seconds after each request and is disabled until it
  reaches zero; then it reads "Resend code" and asks for a new code.
- The countdown is a cooldown of the client. The server keeps its own limit; when it refuses, the
  error line below says so through the typed error of the service.

**Errors (frames 110, 111, 114, 115).** The copy follows the frames, and says no more than the
app knows:
- the code could not be sent: the field border in error, and "We couldn't send the code. Check
  the address and try again."
- the code was not accepted: the six cells in error, the digits kept, and "That code is wrong or
  has expired. Check the latest email, or send a new code."
Both are announced (`accessibilityRole="alert"`). Map them to the typed errors of
`apps/mobile/src/data/auth/types.ts`; an error that maps to neither keeps the message of
`authErrorMessage`.

**The entry step (frames 61 and 62).** "Continue with email" takes the leading `mail` icon of
`SecondaryButton`. The Apple button stays the native one. The Google button keeps no mark (a
recorded deviation).

**Text styles.** The three literal sizes and weights of PR 47 (the label, the address in bold, the
word "or") become text styles of `useTokens().type`.

**One additive change in the design system is allowed:** `CodeField` gains `autoFocus?: boolean`
(default false), with its test. Nothing else under `apps/mobile/src/design` changes.

**Not built, as before:** the segment "Sign in | Create account", "Forgot password?", the
reset-link screen, the back button of the entry step, the privacy line about training models, the
footnote about Terms, the G mark.
