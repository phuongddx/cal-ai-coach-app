## Shape

- One model file per Swift flow (`profileModel.ts`, `settingsModel.ts`, `targetEditModel.ts`), each
  with constructor injection. Jest builds them with test doubles.
- **Owner id.** The user of the session when one exists (`getSessionStore().getSession()?.user.id`),
  otherwise `DEMO_USER_ID` from `apps/mobile/src/data/repos/seedDataManager.ts`; the route file
  passes it.
- **Profile (PR-01).** The plan line comes from the entitlement state as in `ProfileFlow.swift`. If
  the Swift flow reads a stored entitlement that no RN module keeps yet, take it as an injected
  value, have the route pass the free state, and say so in the findings.
- **Settings (PR-02).** The locked copy of `SettingsDetailView.swift`; `SettingsTests` twinned. The
  subscription card is display-only with inert buttons (the old app has no store code): copy it as
  it is, add nothing.
- **ED-safe switch (the write half of PL-08).** The switch calls `setEdSafeMode` from
  `apps/mobile/src/design/edSafe.ts` and stores the value in the `app_settings` table under the key
  `edSafeMode`, as `'1'` or `'0'`, through `writeAppSetting(getDataEnvironment().db, ...)`. U-51
  reads the same key at launch in parallel: do not change the key or the value format. The switch
  re-renders every screen through the design hooks (I7): the feature holds no policy branch.
- **Account deletion entry (PR-02).** The entry asks for confirmation with the Swift copy, then
  calls an injected `deleteAccount()`. The route binds it to `deleteAccount({ auth:
  getSessionStore().bearer, baseUrl: resolveBaseUrl() })` (`deleteAccount` and `resolveBaseUrl`
  come from `apps/mobile/src/data/api`), followed by the sync store's `reset()`
  (`getSyncRuntime().then((runtime) => runtime.store.reset())`) and the sign-out of
  `getAuthServices()` (`signOut()`). U-51 replaces that binding with its reset flow; name it in the
  findings.
- **Target edit (PR-03).** The sheet reuses the wheel fields of the design system; every save goes
  through `TargetsEngine` and `getDataEnvironment().targets.saveTarget`, then `notify`.
- **OB-09.** In `PlanRevealScreen.tsx`, wrap the kcal hero and the weekly range in `EdSafeCollapse`
  from `apps/mobile/src/design`. In ED-safe mode both are not rendered (a test); in normal mode the
  screen does not change (the existing tests keep passing).
- **Identifiers.** Every `accessibilityIdentifier` of the Swift views becomes the `testID` of the
  same element (same string). Put the table in `parity-detail/profile-settings.md`.
- **Route.** `(tabs)/profile.tsx` and `settings.tsx` default-export the screens and nothing else:
  no tests under `src/app`. They are the only files of the feature that import `getDataEnvironment`,
  `getSessionStore`, `getSyncRuntime` and `notifyLocalMutation`.
