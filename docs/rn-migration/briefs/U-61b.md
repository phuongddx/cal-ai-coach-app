## Goal

One document tells the unit that restyles a screen exactly what to build: for every Ember frame,
what it shows from top to bottom with its copy verbatim, which RN screen implements it today, which
identifiers must survive, what differs between the frame and today's screen, and which of its
behaviors need something the app or the backend does not have.

## Scope

Writable, nothing else: `docs/design/ember/FRAMES.md`, `docs/rn-migration/findings/U-61b.md`.

## Shape

`docs/design/ember/FRAMES.md`, one section per frame, in the order of the canvas:

1. **Frame:** caption, section anchor, appearance (light, dark, ED-Safe), size class if it matters.
2. **Shows:** the elements from top to bottom (component, text verbatim, icon, color token), the
   interactions (what a tap does), the sheet detents.
3. **Implemented today by:** the RN file paths, or "no screen yet".
4. **Identifiers that must survive:** every `testID` and accessibility label of today's RN screen,
   and the `accessibilityIdentifier` of the Swift screen it replaced (`grep` both).
5. **Differences from today's screen:** each element, copy string, token or position that must
   change.
6. **Behavior the frame needs:** what the app cannot do yet, and whether it needs a new endpoint,
   a new native dependency, a StoreKit product, or only client work. The plan already lists
   Analyzing with server stages, haptics and billing as follow-ups: confirm or correct that.
7. **Parity rows:** the ids of `parity.tsv` the frame covers.

Then two tables at the end: parity row to frames (every row whose `ember` column is not `-`), and
the frames or screens the design does not show (for these the plan says `derived`: name the nearest
frame to derive from).

Count and quote with commands where you can (`grep -c "testID"`, `grep -o` of copy strings).
