## Why

The app compiles with the React Compiler (`experiments.reactCompiler: true` in
`apps/mobile/app.config.ts`). The compiler assumes that a value which keeps its identity did not
change. A feature model is one mutable object: the views subscribe to it with
`useSyncExternalStore(model.subscribe, model.getSnapshot, model.getSnapshot)`, throw the snapshot
away and then read the model in render (`model.eatenKcal()` and so on). On the Simulator that is a
screen which never moves after a save: you saw it on the diary day sheet during U-74e (after Save
or Delete the toast came up while the row and the totals stayed at the old numbers), and you fixed
it in a local patch that is saved at
`docs/rn-migration/evidence/transcripts/u74e-compiler-fixes.patch` on the branch of PR 62 (the part
on `FoodSearchView.tsx` is already on main through PR 37; the part on `DiaryDayView.tsx` is on no
branch). Jest never saw it because Jest does not run the compiler. The same shape of code is in
other screens.
