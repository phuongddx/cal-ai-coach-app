### `scripts/rn/native-slot.sh`

`prepare`: in the native worktree, `git status` clean, `df -h /System/Volumes/Data` (stop under
6 GB free), `export LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8`, `cd apps/mobile && npx expo prebuild
--platform ios` (with `--clean` when `app.config.ts` changed since the last build). `release`:
remove `apps/mobile/ios/Pods` and `~/Library/Developer/Xcode/DerivedData/CoachCal-*` only (never
another project's). Document both in `docs/rn-migration/build-recipe.md`.

### `scripts/rn/check-artifact-compliance.mjs <path to .app>`

Replaces `native/scripts/check-artifact-compliance.sh` for the RN app. Reads the built bundle with
`codesign -d --entitlements :- <app>` and `plutil`/`plistlib` through `node:child_process` or plain
file reads, and fails unless: entitlements contain HealthKit, HealthKit background delivery, Sign in
with Apple and the App Group `group.com.nextlabs.coachcal`; `Info.plist` contains the camera and the
two Health usage strings, `CFBundleURLSchemes` with `coachcal`, bundle id `com.nextlabs.coachcal`,
`NSSupportsLiveActivities`; `PrivacyInfo.xcprivacy` exists in the bundle with tracking false and the
three collected data types of the old manifest; no file named like a secret (`.p8`, `.p12`, `.pem`,
`.jks`, `.mobileprovision`) is inside the bundle. Plain Node, no dependency.

## Build and run (only you)

```sh
bash scripts/rn/native-slot.sh prepare
cd apps/mobile && CI=1 npx expo run:ios --no-bundler --device 85024D2F-71DE-43C0-8E11-CE58F4578FC3
```

The first build is a full build: about 25 minutes, about 5.3 GB (log to a file in the log
directory, long timeout, never rerun a timed-out build unchanged). Then Metro and the dev client:

```sh
cd apps/mobile && npx expo start --dev-client --port 8081      # not with CI=1
xcrun simctl openurl 85024D2F-71DE-43C0-8E11-CE58F4578FC3 "exp+coachcal://expo-development-client/?url=http%3A%2F%2Flocalhost%3A8081"
xcrun simctl io 85024D2F-71DE-43C0-8E11-CE58F4578FC3 screenshot docs/rn-migration/evidence/PL-17/first-launch.png
```

Start Metro and drive the app inside one script, as the spike recipe says (background jobs can die
with the command that started them).

## If something cannot build

Do not swap in another package and do not patch `node_modules`. Leave the package out of the
manifest and its config entry out, keep the rest building, and report the package, the exact error
and the doc page that explains the limit.
