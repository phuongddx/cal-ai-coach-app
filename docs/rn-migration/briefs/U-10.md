## Shape

- One file per Swift source, same names in camelCase, all exported from `packages/core/src/index.ts`.
- Swift enums with associated values become discriminated unions (`{ kind: 'case', ... }`). Swift
  `clamp instead of throw` stays clamp: inputs that cannot be handled return the clamped value or a
  flag, never throw.
- `SyncEnvelope.swift`: the wire types already exist as zod schemas in
  `packages/api-contract/src/sync.ts`; do not duplicate them and do not add zod to `packages/core`.
  Port what the Swift file does beyond types, as pure functions over structural types:
  `validateAcknowledgementSet(operations, acknowledgedIds)` (the ack set must equal the request),
  the cursor rules, `rejectUnknownKeys` behavior where it is logic and not decoding, and the record
  merge that uses `CanonicalVersion`.
- `NotificationScheduler.swift`: port only the pure rule part (which of `meal.lunch`, `meal.dinner`,
  `eod.recap` should be pending for a given day, time and the set of already logged slots). Calls to
  the notification center are not core; list them in the findings file so U-42 wires them.
- `ProofRecord.swift`: port the types and the serializer including redaction. The
  `NSRegularExpression` becomes a JavaScript `RegExp` with the same pattern.
- `WidgetSnapshot.swift`: compare it field by field with
  `apps/mobile/src/data/widget/snapshotFromMeals.ts`. If the TypeScript shape differs from the Swift
  one, change the TypeScript to match Swift and update its test; the spike widget (`src/widgets/CaloriesWidget.tsx`)
  must keep type-checking (rename the fields it reads, nothing more). List every difference in the
  findings file.

## Method (test first, one Swift test file at a time)

1. Create the Jest file next to the source, with one `it(...)` per Swift `@Test` and the same
   behavior sentence as the test name.
2. Run it and see it fail.
3. Port the source until it passes.
4. Move to the next file.

Run one workspace: `npm test --workspace @coachcal/core`. TypeScript: `npm run typecheck --workspace @coachcal/core`.

DayKey tests must run under three time zones. In the Jest file set `process.env.TZ` in `beforeAll`
and restore it in `afterAll`, with one describe block each for `Asia/Ho_Chi_Minh`,
`America/Los_Angeles` and `Pacific/Kiritimati`.
