## Tasks, in this order

1. **Rename the legacy column.** In `apps/api/migrations/*.sql` the column `supabase_user_id`
   (`entitlements`, `webhook_events`, the function variables and the JSON key `supabaseUserId`)
   becomes `user_id` and `userId`. Replace the workaround
   `['supabase', 'user', 'id'].join('_')` in `apps/api/src/testing/sqlHarness.ts` with the plain
   name. The relocated contract `packages/api-contract/src/contracts/webhook.ts` keeps its legacy
   field `supabaseUserId` (it is a copy of the Deno file): map it to `userId` in one place in the API
   and say so in `parity-detail/backend-auth.md`.
2. **Real sessions in `requireUser`.** The access token is a JWT signed by the API (`jose`, HS256 or
   ES256, 15 minutes) with `sub` (user id) and `sid` (session id); the middleware verifies it and
   checks through a SECURITY DEFINER function that the session is not revoked. Dev tokens keep
   working only when `AUTH_DEV_TOKENS=1`. `jose` 6.2.18 is an ES module: check whether `require('jose')`
   works under your Jest transform (Jest 30.5 can require ES modules) or switch `apps/api` to ES
   modules; U-11 wrote no `require`, `__dirname` or `import.meta`, so both are open.
3. **Schema.** A new migration adds `users`, `auth_identities` (user, provider, the provider's subject,
   the e-mail password hash, the Apple refresh token), `auth_sessions` (refresh token hash, expiry,
   revocation, replaced by), `auth_otp_codes` (hash of the code, expiry, attempts, used at) and
   `auth_one_time_codes` (the Google exchange code). The API role `coachcal_api` gets no privilege on
   these tables: every read and write goes through narrow SECURITY DEFINER functions with the
   `app.user_id` convention U-11 set (`auth_*`, `account_delete`, `webhook_apply`). Take `EXECUTE` on
   `apply_webhook_event` away from the API role and route the webhook through `webhook_apply`, which
   validates its input. This supersedes the list of five
   functions in spec.md invariant I2: the API role executes only what it needs and has no privilege
   on any table; that is the invariant. Passwords: scrypt from `node:crypto`. The Apple refresh token is encrypted at
   rest (AES-256-GCM from `node:crypto`, key derived from `AUTH_ENCRYPTION_KEY`).
   `account_delete()` removes the user's rows, revokes the sessions and returns the Apple refresh
   token so the route can call Apple's revoke endpoint.
4. **Routes per the contract.** Apple: verify the identity token against Apple's JWKS (`jose`), check
   `aud` is `APPLE_BUNDLE_ID`, `iss` is `https://appleid.apple.com`, and that the `nonce` claim equals
   the SHA-256 of the raw nonce; when an authorization code is present, exchange it at
   `https://appleid.apple.com/auth/token` with a client secret that is an ES256 JWT signed with the
   `.p8` key (`APPLE_TEAM_ID`, `APPLE_KEY_ID`, `APPLE_PRIVATE_KEY_PATH`). Which `client_id` the
   exchange needs (the Services ID or the bundle id) is decided from Apple's documentation, not from
   memory: quote the page in the findings file. Google: `start` redirects to Google with `state`,
   `callback` exchanges the code once at Google's token endpoint (`GOOGLE_CLIENT_ID`,
   `GOOGLE_CLIENT_SECRET`, redirect URI `/v1/auth/google/callback`), verifies the ID token with
   `jose` against Google's JWKS, stores a one-time code and redirects to
   `coachcal://auth/google?code=<one-time code>`; `exchange` turns it into a session once.
   E-mail: `POST /v1/auth/email` signs an existing user in; `otp/request` sends a six-digit code
   through a sender chosen by `OTP_SENDER`: `log` (the code goes to the server log, development only)
   or `resend` (its HTTP API through `fetch`, `RESEND_API_KEY`, `OTP_FROM`); `otp/verify` creates the
   user when missing. `refresh` rotates the refresh token (the old one stops working at once),
   `signout` revokes, `DELETE /v1/account` calls `account_delete()` and revokes the Apple token at
   `https://appleid.apple.com/auth/revoke`. A provider whose variables are missing answers
   `503 UPSTREAM_ERROR` with a detail that names the variable class, never its value.
   Rate limits: per e-mail address and per IP on OTP request, OTP verify and e-mail sign-in
   (in memory is enough for one instance; say so). A missing server secret at startup is an error
   at startup, not at the first request.
5. **Sync on the ported RPCs.** `POST /v1/sync/push` and `/v1/sync/pull` call the ported
   `sync_push` and `sync_pull` as `coachcal_api` inside `withUser`, with the exact acknowledgment-set
   semantics of the Deno tests; the wire contract (`packages/api-contract/src/sync.ts`) does not
   change. The 11 existing tests of the spike's sync routes must pass against the real functions.
6. **Webhook.** `POST /webhooks/revenuecat`: HMAC over the raw body with `RC_WEBHOOK_SIGNING_SECRET`,
   then `RcWebhookEnvelopeSchema`, `toWebhookEvent`, and `webhook_apply`. Port the 33 cases of

7. **Build and run.** `npm run build` in `apps/api` produces `dist/` with `tsc`; `npm start` runs it
   and runs the migrations before it serves when `RUN_MIGRATIONS_ON_START=1`.
8. **Deploy kit** in `apps/api/`: `Dockerfile` (`node:24-slim`, multi-stage, not root at runtime),
   `deploy/docker-compose.yml` (api, `postgres:17`, `caddy:2`), `deploy/Caddyfile` (automatic HTTPS,
