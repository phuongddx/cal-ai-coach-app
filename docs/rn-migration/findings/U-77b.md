# U-77b findings — Sign-in on Ember

Worker: Worker-S1. Parity row AU-01. Stage A (JS and Jest only). Stage B (Simulator evidence) has not run: no slot was given.

The behavior does not change: Apple, Google, and an e-mail code (`requestCode`, `verifyCode`). The screen is now two steps of one route.
The entry step follows frames 61 and 62. The e-mail step takes the look of frames 63 to 67, with a code where the frames have a password.

## Design changes

- Entry step (`EntryStep.tsx`): top block with the 64 pt app tile (`assets/brand/ember-ring.png`, 192 px, made from `docs/design/ember/icon/flat/AppIcon-light-1024.png`), the title "Sign in to keep your diary safe", one subtitle, one privacy line with the shield icon. Bottom block above the home indicator: Sign in with Apple (black in light, white in dark), Continue with Google, an "or" divider, Continue with email.
- E-mail step (`EmailStep.tsx`): header row (Back, "Email" centered, 44 pt spacer), title "Sign in with email", a native text field "Email" (token-drawn), then after the code is sent one sentence "We sent a code to **e-mail**." and a native text field "Code" (accessibility label "6-digit code"). `PrimaryButton` docked at the bottom: "Send code", then "Verify".
- One error line (`ErrorLine.tsx`): alert icon plus text in `errorInk`, role alert. It shows under the fields on the e-mail step and above the buttons on the entry step. A step change clears it.
- The whole form is still one busy state (`auth.form`, `pointerEvents` none while busy); Back keeps the typed e-mail and the requested code.
- All colors, spacing, radii and type come from the tokens; `grep -rnE "#[0-9A-Fa-f]{6}" apps/mobile/src/features/auth` and the ED-safe grep print nothing.

## Deviations

- **Segment (Sign in / Create account), "Forgot password?", the password notes and the reset-link screen are not built.** The app signs in by a code that serves a new address and a known one; the API has no password creation and no reset route.
- **No back button on the entry step** (frame 61): the root gate makes sign-in the first screen, nothing is behind it.
- **Lock line not drawn** ("never used to train models"): a promise the repository can't prove. `PRIVACY_LINES` in `EntryStep.tsx` is one array; adding the line is one entry.
- **Terms/Privacy footnote not drawn:** no pages exist.
- **Google mark not drawn** (no icon), so the Google button is text only.
- **Radius:** the brief says "14 pt (radius.btn)", but `radius.btn` is 18 and `radius.md` is 14. The tile and the Apple button use `radius.md` (14), as the frame draws. `SecondaryButton` keeps 18 (gap item 6).
- **Title size** 34 (`typography.title` with the `largeTitle` line height) against 32 in the frame, to stay on a token.
- **Header built from `GlassIconButton` and a text**, not `SheetHeader`: `SheetHeader` names its back button `<testID>.back`, the required identifier is `auth.emailBack`.
- **`ErrorLine`, not `BannerNote`:** a banner is a card; frames 64 and 66 show an inline line.
- `auth.signInEmail` sits directly on the `SecondaryButton`'s outer view; the other buttons keep wrapper views.
- Dock helper notes of frames 63 to 67 are not drawn (they are about passwords).
