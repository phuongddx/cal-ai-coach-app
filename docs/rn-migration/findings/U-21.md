# U-21 findings: backend auth, sessions, sync RPCs, webhook, deploy kit

Unit of `docs/rn-migration/plan.md`. Worker: Worker-S1. Branch `rn/u-21-backend-auth`. Goal: the Hono API
(`apps/api`) does everything Supabase did, so the app needs nothing from Supabase.

## What was built

- **Rename.** `supabase_user_id` is `user_id` everywhere in `apps/api` (`grep -rn "join('_')" apps/api/src` prints
  nothing). The one place the contract's legacy field `supabaseUserId` becomes `userId` is `toApplyEvent` in
  `apps/api/src/webhook/route.ts` (`packages/**` may not be edited in this unit).
- **Migration `20260920000000_auth_accounts.sql`.** Tables for users, identities, sessions, e-mail codes, Google
  one-time codes; narrow `SECURITY DEFINER` functions with `search_path=''`; `coachcal_api` has no table privileges,
  only EXECUTE on the functions it needs. `apply_webhook_event` is not executable by the API role; `webhook_apply`
  validates input first. Privilege tests: `auth/authPrivileges.test.ts`.
- **Sessions.** HS256 access token (iss `coachcal-api`, sub, sid, 15 min). Opaque rotating refresh token
  `<sid>.<secret>`; only its sha256 is stored; presenting an already rotated token revokes the whole session; 30 days.
  `requireUser` accepts a session token, and the dev tokens only when `AUTH_DEV_TOKENS=1`.
- **Sign-in paths.** Apple (identity token, nonce, code exchange, encrypted refresh token for later revoke), Google
  (system browser, signed state plus cookie plus nonce, one-time code exchange), e-mail and password (never creates a
  user), e-mail code (OTP: keyed hash, 10 min, locked after 5 wrong attempts). Providers answer 503 `UPSTREAM_ERROR`
  naming the missing variables until configured.
- **Account deletion.** `DELETE /v1/account` runs `account_delete()` and then revokes the Apple token after the commit
  (a revoke failure is logged and still answers 200).
- **Sync adapter.** `apps/api/src/sync.ts` maps the contract routes onto `sync_push`/`sync_pull`.
- **Webhook.** `POST /webhooks/revenuecat`, HMAC-SHA256 over `${t}.${raw}`, 300 s tolerance, empty secret gives 401.
- **Deploy kit.** `apps/api/Dockerfile`, `apps/api/deploy/` (compose with PostgreSQL 17, one-shot migrate, API, Caddy;
  initdb role script; `backup.sh`), `apps/api/.env.example`, root `.dockerignore`, Vietnamese guide
  `docs/rn-migration/deploy-vps.md`. Smoke scripts: `scripts/rn/smoke-auth.sh`, and a real-session case in
  `scripts/rn/smoke-scan.sh`.

## Decisions the owner should know about

1. **`build` is a compile gate, runtime uses tsx.** The workspace packages `@coachcal/api-contract` and
   `@coachcal/core` have `main: src/index.ts` (TypeScript source), so a compiled `dist/` cannot run under plain `node`.
   `npm run build` type-checks and emits to the ignored `dist/`; `npm start` is `tsx src/index.ts`; the Docker CMD is
   `node --import tsx src/index.ts`. Consequence: the image installs the api workspace's dev dependencies (tsx) and is
   721 MB. Fix later by giving the packages a built `main`.
2. **Global `serverVersion`.** The ported `sync_push`/`sync_pull` use one monotonic version for all rows of a user, while the
   spike had a per-record counter. The adapter follows the SQL. Result: `scripts/rn/e2e-sync.sh` (spike, outside this
   unit's writable files) now fails at its step 1 line "C serverVersion: expected [1], got [2]" because it expected a
   per-record counter. The script was not changed; the owner decides whether to update its expectation.
3. **Cross-user push is 403 `UNAUTHORIZED`.** Pushing a record id that belongs to another user is rejected by the SQL function and the adapter returns 403 (the contract had no such case) (test:
   `app.test.ts > denies a push that targets another user's record with 403 and leaves that row unchanged`).
4. **429 uses `VALIDATION_ERROR`.** The contract has no rate-limit code, so a limited request answers 429 with
   `VALIDATION_ERROR` and `Retry-After: 900`.
5. **Rate limits are in memory.** Correct only with one API instance (what compose runs). Limits: code request 5/h per
   e-mail and 20/h per IP; code check and e-mail sign-in 10 per 15 min per e-mail and 30 per 15 min per IP. The client
   IP is the last `X-Forwarded-For` entry (Caddy replaces a client-supplied header), else the socket address.
6. **Apple `client_id` is the bundle ID** (native flow). A Services ID is needed only for a web flow, which the app does not have.
   Apple `givenName`/`familyName` are not stored (the API has no column for them; not checked against the old app).
7. **Google callback errors redirect** to `coachcal://auth/google?error=<reason>` instead of showing JSON, because the browser is the system browser.
8. **No route sets `users.password_hash`.** E-mail and password sign-in works for users that already have a hash; no route in the API creates one (not checked against the old app). Say so if a "set password" feature is expected.
9. **Unused devDependency.** `@electric-sql/pglite` is in `apps/api/package.json` and unused; removing it needs a package.json edit that
   this unit may not make. npm also warns that the `esbuild` and `@parcel/watcher` install scripts are "not covered by allowScripts"; tsx still runs.
