# U-11 findings: backend scan pipeline (`apps/api`)

Branch `rn/u-11-backend-scan`. Parity rows BE-01, BE-02, BE-03, BE-08, BE-09, BE-10, BE-11; the
per-row behaviours and proving Jest cases are in `docs/rn-migration/parity-detail/backend-scan.md`.
Evidence was produced against a throwaway PostgreSQL 17 started by `scripts/rn/start-api.sh`.

## What was built

- `POST /v1/scan`, `POST /v1/barcode/resolve`, `POST /v1/foods/search` under `/v1` behind one
  `requireUser` middleware (dev tokens only when `AUTH_DEV_TOKENS=1`, read per request).
- Ported domain files with the Deno layout: quota, entitlement, routing, hiddenFat, the grounding
  cascade (FDC, OFF, FatSecret stub, cache store), the VLM providers (Gemini, fixture), the scan
  pipeline. `fetch` is injectable the way the Deno `fdcFetch.impl` seam was (`fdcFetch`, `offFetch`,
  `geminiFetch`, `overrideVlmProvider`, `ScanDeps.tiers`).
- `apps/api/migrations/` with the three ported migrations and one new helper migration, applied by
  `src/migrate.ts` as `coachcal_owner`.
- Ten Jest twins (one `it` per `Deno.test`, same sentence) plus `privileges.test.ts`.

## Findings

1. **A fourth migration was needed** (`20260914000002_api_helpers.sql`). The Deno code read and wrote
   `food_cache` and `entitlements` with the service-role client. The API role holds no table
   privileges (I2), so those two reads and one write became three narrow SECURITY DEFINER functions:
   `cache_get`, `cache_put`, `get_entitlement`. The brief says "five functions"; the database now has
   those five plus these three (and `sync_push`, `sync_pull`). Each requires `app.user_id`.
2. **`persist_scan` got a caller-ownership check** (errcode 42501 when the scan or item rows name
   another user). The original relied on the service-role caller being trusted. Proven by
   `privileges.test.ts > persist_scan rejects another user's rows before any write`.
3. **`apply_webhook_event` is granted to `coachcal_api`**, as the brief says for all five functions.
   It is a webhook-only function; U-21 must gate it (webhook secret check) before the route exists.
4. **BE-03 method mismatch.** `parity.tsv` says `GET /v1/foods/search`; the brief and the Deno
   function use a JSON body, so the route is `POST`. `parity.tsv` was not touched (forbidden path).
5. **postgres.js jsonb pitfall.** A jsonb parameter must be a raw object or `sql.json(...)`. A
   `JSON.stringify` string is stored as a JSON string (double-encoded). This silently broke
   `persist_scan`, `cache_put` and the test cache seeder, with no error: the cascade just missed.
6. **`maxWorkers: 1`** in `apps/api/jest.config.js`. The SQL suites share one database and the same
   cache keys (`search:banana`, ...), so files must run serially.
7. **Parity gate vs a column name.** `scripts/rn/parity-check.mjs` matches `supabase_user_id`
   case-insensitively in `.ts` files. The ported `entitlements` table keeps that column (primary key
   `(app_user_id, entitlement_id)`). The TS code builds the name as `['supabase','user','id'].join('_')`
   (`src/entitlement.ts`, `src/testing/sqlHarness.ts`); SQL files are not scanned. U-21 may rename the
   column in a later migration, which removes the workaround.
8. **`GET /health` body is `{ ok: true, service: 'coachcal-api' }`**, the spike test's shape, which
   satisfies the `{ ok: true }` acceptance. The spike sync routes and `app.test.ts` are untouched.
9. **Transactions and refunds.** Each DB step (claim, cache read, cache write, persist) is a separate
   short transaction through `withUser`, as the Deno RPC calls were. There is no quota refund when the
   VLM or a provider fails after the claim; the Deno code had none either, and a replayed `scanId`
   does not consume a second credit.
10. **Skipped SQL suites say so loudly.** Jest hid the `console.warn` of skipped files in a full
    non-TTY run, so `describeSql` also writes the `[sql-skip]` line to stderr. Without the database,
    `npm test` is green: 5 suites skipped entirely, 71 cases pass and 52 are skipped.
11. **One live test skips.** `gemini: live call against the real API ...` needs `GEMINI_API_KEY` and
    skips without it, as the Deno test did. It was not run.
