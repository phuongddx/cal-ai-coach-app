## Swift to RN notes on the module

- `apps/mobile/modules/coachcal-launch-arguments/`: `expo-module.config.json`, `ios/CoachCalLaunchArguments.podspec`,
  `ios/CoachCalLaunchArgumentsModule.swift`, `index.ts`. Autolinking found it with no change to `app.config.ts` or any
  `package.json` (the default `nativeModulesDir` is `./modules`).
- Swift: `Module` with one synchronous `Function("getArguments")` returning `ProcessInfo.processInfo.arguments`.
  The Swift app reads them only under `#if DEBUG` (`DebugLaunchArguments.parse()`); the module keeps that rule and
  returns `[]` in a release build. That branch is **not verified**: no release build was made.
- TS: `readLaunchArguments()` uses `requireOptionalNativeModule`, so a missing module (Jest, an older build) gives `[]`;
  a throwing module or a non-list answer gives `[]`; non-string items are dropped.
- `debug/launchArgs.ts`: `loadLaunchArguments()` asks the module; `applyLaunchArguments(argv)` parses with
  `flagsFromArguments` and applies only the keys that differ from the defaults, so an argument wins over a flag set
  earlier in the launch and an absent argument changes nothing.
- `platform/launchSequence.ts`: new step 0 (load, apply) before the flags and the stored ED-safe mode are read.
  ED-safe at launch is still `flags.edSafe || stored`, so `--ccEDSafe` forces it on and a stored mode survives. A throwing
  reader does not stop the launch. The new deps are optional and default to the real ones, so `rootRuntime.ts` is untouched.
- `(tabs)/index.tsx`: `coachcal://?edSafe=1` removed (`grep -rn "edSafe=1" apps/mobile/src` prints nothing); the route reads
  `getDebugFlags().edSafe`. `coachcal://?seed=1` stays.
- Jest: `loadLaunchArguments.test.ts` (new) and `launchSequence.test.ts`; the touched `src/debug` and `src/platform`
  suites: 10 suites, 70 tests, green.

## What the harness can now do

`app_open [title] [seconds] [launch argument ...]` in `scripts/rn/evidence/lib.sh` terminates the app and starts it with
`xcrun simctl launch <udid> <bundle id> <args>`, then attaches to Metro as before. A timed-out `openurl` after a launch with
arguments is a note, not a failure (the launch reconnects by itself). Without arguments it behaves as before.

`fixedClock real`, and the stored ED-safe mode is the only thing that persists.

## Found on the way

1. **A fresh install shows the Debug console, not onboarding (bug of the root gate, next unit U-81).** With no stored target the
   root gate picks `onboarding`, but the Simulator shows only the always-mounted Debug route (no onboarding screen, no Today).
   Flow 01 `app_install_fresh` + `app_open "Today"` therefore failed on this build. **Temporary** harness workaround in `lib.sh`
   (`_seed_fresh_target`): the first `app_open` after `app_install_fresh` launches once with `--ccSeedNoTargets`, seeds the demo
   persona via `coachcal:///?seed=1`, and stops the app. U-81 reproduces the bug, fixes the gate, proves it on a fresh-install
   Simulator and removes this workaround. The route/gate behaviour itself is not changed here.
2. **`run-all.sh` now ends `0 failed`** (it ended `4 failed` before). Fixed in this unit, in the flows and the helper:
   - `_wait_title` (`lib.sh`): a title that is not a tab-bar RadioButton counts from y > 60, because real screens put their title at
     y about 80 to 120 (Progress: `StaticText` y=78). A tab-bar RadioButton still needs y > 200 (the glass bar reports bogus y).
   - Flow 02 (`02-tabs.sh`): Progress is recognised by its title; Coach and Profile have **no title of their own** (the name exists
     only in the tab bar), so they are recognised by their first section heading, `TODAY'S INSIGHTS` and `GOALS & TARGETS`.
   - Flow 04 (`04-diary-sheet.sh`): the sheet is recognised by its date title (`Friday, Nov 27`, y < 400) plus the `Breakfast` section,
     not by the word "Diary".
   Transcript of the full run: `docs/rn-migration/evidence/transcripts/U-79-run-all.txt` (last line `run-all done: 0 failed`); the five
   per-flow transcripts and the screenshots of that run replace the older ones. Every regenerated screenshot was opened.
3. `app/debug.tsx` still says "Process arguments are read by the native slot (U-50)"; the text is stale (file outside scope). Goes to U-81.
4. Merge order: PR 27 (U-33, the `edSafe=1` switch) merged as e34ebda; origin/main (812e926) is merged into this branch (64add84), so
   this PR no longer depends on anything open.
