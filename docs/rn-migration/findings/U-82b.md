## The three commands of an evidence unit

An evidence unit no longer needs the Simulator of the machine. It works on its own worktree and
branch and captures on GitHub:

1. Trigger the run on its branch (`flows` takes flow names without `.sh`, space separated;
   empty means every flow):

   ```sh
   gh workflow run rn-evidence.yml --ref <branch> -f flows="03-today-seeded 04-diary-sheet"
   ```

2. Wait and read the result (the run's name is "RN Evidence"; the job runs ≤ 60 minutes):

   ```sh
   gh run list --workflow rn-evidence.yml --branch <branch>
   gh run view <run id> --repo phuongddx/cal-ai-coach-app --log-failed
   ```

3. Download the artifact into the unit's worktree and open the screenshots:

   ```sh
   gh run download <run id> -n rn-evidence-<run id> -D <dir>
   ```

   The artifact holds: every file under `docs/rn-migration/evidence/` the run created or changed
   (tracked and untracked), the whole `transcripts/` directory (`run-all.txt` and one transcript
   per flow — the last line of `run-all.txt` reads `run-all done: N failed`), the Metro log of
   run-all (`rn-logs/u14-metro.log`) and the seed phase's Metro log
   (`rn-logs/metro-seed.log`). The exit code of run-all is the number of failed expectations:
   a red job with a green artifact upload means a flow failed — read `run-all.txt` first.

The two runs of the unit (cold and cached build) are distinguished only by time: the native
build is cached under the hash of `package-lock.json`, `apps/mobile/package.json`,
`apps/mobile/app.config.ts`, `apps/mobile/modules/**` and `apps/mobile/plugins/**`; a run on a
tree whose native inputs did not change restores it, and the build step prints
`cache hit (exact key): true` and the build duration.

## What the workflow does beyond the brief's sketch

- **Seed phase before run-all.** `run-all.sh` installs nothing and seeds nothing; flow 01 does
  it (`app_install_fresh`, then part 2: launch `--ccSeedNoTargets`, open the dev client, Today
  seeds the persona). A subset without flow 01 — the proof runs `03-today-seeded 04-diary-sheet`
  — would hit the fresh-install gate at its first `app_open "Today"` and die on the runner. The
  workflow therefore replays flow 01 part 2 inline (Metro on 8081 + `wait-metro.sh`, launch
  `--ccSeedNoTargets`, dev-client URL, polls `axe describe-ui` for "Spaghetti Bolognese" up to
  240 s, re-opening the URLs and tapping the "Open in CoachCal?" dialog away every 20 s), then
  terminates the app and **stops its Metro** — `run-all.sh` starts its own Metro and refuses a
  served port (`metro_start` is fatal on a running Metro, and the brief allows only two
  variables in `lib.sh`). With the full flow set, flow 01 wipes and re-seeds anyway; the seed
  phase is harmless there.
- **`axe` comes from a tap.** The machine's 2.1.1 is not in homebrew-core: the formula lives in
  `cameroncooke/axe`, so the workflow runs `brew tap cameroncooke/axe && brew install
  cameroncooke/axe/axe` and prints the version.
- **Device.** `pick-evidence-device.sh` picks the `iPhone 17 Pro` on the newest iOS runtime of
  the image (same jq shape as `pick-simulator.sh`, narrowed to the name). No match: it prints
  `simctl list devices available` and exits 1, so the job stops before the flows and the owner
  decides.
- **Artifact always.** The collect step runs `if: always()`, so a failed flow, a failed seed or
  a cancel from `concurrency` still uploads.

## lib.sh, two variables

`DEV_CLIENT_URL` is built from `${METRO_PORT:-8081}` (it was hardcoded 8081) and `LOG_DIR` from
`${COACHCAL_LOG_DIR:-<today's machine path>}`. A run with neither variable set behaves as
before; on the runner the workflow passes `METRO_PORT=8081` and
`COACHCAL_LOG_DIR=$RUNNER_TEMP/rn-logs`, which also moves the Metro log (`$LOG_DIR/u14-metro.log`)
into the artifact path.

## The two-refs check

`concurrency.group` is `rn-evidence-${{ github.ref }}`, so two dispatches on two branches run at
once and a newer dispatch on the same branch cancels the older one. Note: `gh workflow run
rn-evidence.yml --ref main` resolves the workflow file **on main**, so the check against main
works only once this pull request has merged (the file is not on main before that); until then
the parallel check is a second branch of the same head.
