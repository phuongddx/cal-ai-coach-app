# U-40 findings — progress and coach

Worker: Worker-G2. Unit of `docs/rn-migration/plan.md`, wave 4. Ports the Progress tab and the
Coach tab (PG-01 to PG-04, CH-01): `apps/mobile/src/features/progress/`,
`apps/mobile/src/features/coach/` (models, screens, tests), the routes
`apps/mobile/src/app/(tabs)/progress.tsx` and `(tabs)/coach.tsx`,
`docs/rn-migration/parity-detail/progress-coach.md`.

## 1. ValueObservation → subscribe-signal refresh, reconcile after every read

Swift's Progress/Coach models ride GRDB ValueObservation; the RN models refresh on the sync
runtime's re-read signal (the same wrapper `src/app/diary.tsx` uses, copied verbatim into both
routes because features cannot import the data seams). The publish order mirrors the Swift loop:
load → publish → `reconcileStreak()`, which saves through EngagementRepository when the outcome
differs and publishes the updated streak row directly (the Swift observation would deliver exactly
that row on its next pass). The Swift polling loops in the tests (`for _ in 0..<100 { … 20 ms }`)
collapse to a single awaited `refresh()` — the RN refresh is deterministic, so the twins keep the
Swift assertions but not the polls.

## 2. `veryShortWeekdaySymbols` are single letters

`WeeklyEnergyColumn.dayInitial` renders Calendar.veryShortWeekdaySymbols — on iOS these are "S",
"M", "T", "W", "T", "F", "S", not three-letter abbreviations (shortWeekdaySymbols are those). The
first draft used `Sun/Mon/…` and the twin's `count == 1` filter caught it immediately. The port
uses the single-letter table; the twin validates the rendered initials against `Intl` narrow
weekday names as its independent source (the Swift test checks against the calendar's own symbols).

## 3. Streak twin: the seeded week plus the alive floor reproduce 12

The seeded streak row is 12/18 with `lastLoggedDay = yesterday`, and the seed logs exactly 7 days.
Reconcile therefore recounts 7 and keeps 12 through the alive floor (`max(outcome, persisted)`),
then overwrites `lastLoggedDay` with today (the max of the observed day-set) — the row the twin
asserts (12/18/1). The 40-day case (WR-04) runs on a fixture WITHOUT the seed: only the streak row
plus 40 detail-less diary entries, exactly as the Swift test builds its pool, and the 730-day
streak window carries them all.

## 4. ED-safe: one wrap, zero branches

WeeklyEnergyView wraps its whole Card in `EdSafeCollapse` from the design barrel — the exact
placement of the Swift `.edSafeHidden()` on the card. `grep -rn "edSafe" features/progress
features/coach` prints nothing (checked after writing every file). The ED-safe proof lives at two
levels: the WeeklyEnergyView twin ("renders nothing while the mode is on", `screen.toJSON()` is
null) and the ProgressView stack backstop (the card vanishes while weight trend and achievements
stay, matching `progressEdSafeHidesWeeklyEnergy`). The Coach review card needs no feature branch —
the DS `WeeklyReviewStats` owns the stat swap, asserted on the CoachView screen too.

## 5. Screens: three Swift identifiers, wrapper Views as in diary

The Progress/Coach Swift sources declare exactly three accessibilityIdentifiers
(`progress.logWeight`, `progress.closeWeightSheet`, `progress.saveWeight`); the first and third
follow the diary convention — a wrapper View carrying the string around the DS `PrimaryButton` —
so the feature touches no DS component internals and the tests press the inner button, the close
is a plain Pressable. The wheel value, the weekly-energy column labels and the streak/badge/photos
a11y labels port as labels, not identifiers. The weight wheel renders all 2,101 domain rows
(`WheelField` has no virtualization); under jest that is one slow-but-fine render, on device it is
the same trade the DS wheel already made for the serving/duration fields.

## 6. Floating-point dust in the seeded trend

The seeded weights (`82.4 − index × 0.35`) leave the oldest log at `79.95000000000005`, so the
seeded trend reads `start − latest = −2.4499999999999286` → "2.4 kg gained" (toFixed and Swift's
`%.1f` agree on the rounding). The screen test asserts `/kg gained/` and the exact header values
("82.4 kg", "74.0 kg") instead of pinning the direction-row dust; the exact copy strings are
pinned through `trendCopy` with clean inputs.
