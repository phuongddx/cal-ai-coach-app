# U-30 Scan flow: findings

Status: **partial**. Model, capture seam, screens and route are done and tested. The Simulator evidence
(SC-02..SC-07, DB-01) is **not captured**: this machine has no iOS Simulator runtime.

## Blocker: no Simulator

- `xcrun simctl list runtimes` prints only the header, `xcrun simctl list devices` prints no device,
  `xcrun simctl runtime list` reports 0 disk images, so UDID `85024D2F-71DE-43C0-8E11-CE58F4578FC3`
  (iPhone 17 Pro, iOS 26.4) does not exist (`Invalid device`).
- Installing a runtime is a multi-GB download and creates a device; neither is in this unit's brief. Not done.
- Not produced: SC-02 viewfinder, SC-03 analyzing, SC-04 review (200 light and dark, 402, 404, 422), SC-05, SC-06,
  SC-07, DB-01. Nothing was written under `docs/rn-migration/evidence/`.
- Ready for whoever has a runtime: `coachcal://scan?scenario=200&capture=fixture` (also `402`, `404` with
  `mode=barcode`, `422`, `mode=text`), tap by label (`Fix Issue`, `Save to Lunch`, `Undo`). The route accepts these
  query parameters only under `__DEV__`. No flow script was committed because none could be run.

## What was ported

`features/scan/`: `scanModel.ts` (pure state machine with injected `api`, `persistence`, `notify`, `activity`,
`now`, `readIsEdSafe`), `scanPersistence.ts` (one `recordUpserts`, `recordTombstone` on undo), `scanCapture.ts`
(fixture and device capture services), `scanActivity.ts` (PL-12 port, no-op), and one view per Swift view. The route
`app/scan/index.tsx` is the only file that imports `getDataEnvironment`, `getSessionStore`, `getDebugFlags` and
`notifyLocalMutation`.

## Decisions

- Meal picker is a chip row (RN has no menu Picker).
- "Search manually" and "Log manually" are route callbacks that close the flow. The food search and add-food routes
  belong to other units.
- Label mode uploads the image. Swift sent OCR text. The contract requires `imageBase64` for photo and label.
- `manipulateAsync` is used for the resize: deprecated in expo-image-manipulator but working and mocked; the context
  API is not mocked.
- `EdSafeCollapse` and `ScanThumb` are built inside `features/scan` (the design system lacks them). The owner decides
  whether they move to `src/design`.
- The Open Settings button is found by role and name in tests because the design `PrimaryButton` has no
  `accessibilityLabel` prop.
- `update` of the Live Activity port is unused by the model, as in Swift. The content field `isEdSafe` maps to the
  native `edSafeMode` in U-43.
- Quota without an entitlement falls back to a free-tier default.
- `QuotaReachedView` and `NeutralPlansSheet` live in `QuotaReachedView.tsx`.
- Query parameters `scenario`, `capture`, `mode`, `meal` are a `__DEV__`-only stand-in for launch args until U-51.
- The route imports `edSafeMode` from the design barrel to feed `readIsEdSafe` (a read, not a branch).
- I7: the word `edSafe` must not appear under `features`, comments included (the grep is a plain match). Prose says
  "ED-safe". `useEdSafeHidden` and `useEdSafeMode` do not match the case-sensitive grep.

## Pitfalls

- sql.js fixture `findMany()` returns raw snake_case rows: read through the repositories.
- `StyleSheet.absoluteFillObject` is missing in RN 0.88.
- RNTL: stepper value is asserted with `toHaveAccessibilityValue`; `ChipOption` testID is on the pressable
  (`chip-option:<title>`), not on a wrapper; hidden containers need `{includeHiddenElements:true}`; a component test
  needs the React-dedup `jest.mock` preamble.
- `axe` sees only labels and accessibility identifiers, never testID (U-14).
- BSD `sed -i` with `&&` aborts a chain: edit with a script or a file write.
