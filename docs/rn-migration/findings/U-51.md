# U-51 findings — composition root, root gate, debug console

Worker: Worker-S1. Unit of `docs/rn-migration/plan.md`. Ports `RootView.swift`, the launch and
account-reset parts of `AppEnvironment.swift`, its telemetry allow-list and `DebugLaunchArguments.parse`
to `apps/mobile/src/platform/**`, `src/app/_layout.tsx`, `src/app/debug.tsx` and `src/debug/launchArgs.ts`.
Per-row evidence: `docs/rn-migration/parity-detail/root.md`.

## 1. The gate re-decides without touching a route file

`decideRootGate` is pure. `rootController` is an external store (`useSyncExternalStore` in
`useRootGate.ts`) that re-decides on three events: the session store's `onChange`, the debug flags and
the sync runtime's local-write notification. `_layout.tsx` renders `Stack.Protected` groups from the
route, so signing in, saving the onboarding target or flipping `--ccRequireSignIn` moves the user with
no edit in `sign-in.tsx` or `onboarding/index.tsx`. Adding no file under `src/app` kept
`routes.test.tsx` green.

## 2. Deviation from Swift: the target is read for the demo persona and the session user

Swift asks `activeTarget` only for `DEMO_USER_ID` at launch (`AppEnvironment.swift` ~411), while
onboarding saves the target under `currentUserId`. A signed-in user would be sent through onboarding on
every launch. `targetOwners(session)` returns `[DEMO_USER_ID]` when signed out and
`[DEMO_USER_ID, session.user.id]` when signed in, and the gate re-reads after sign-in. Covered by
`launchSequence.test.ts` and `rootController.test.ts`. If parity with the Swift behavior is wanted
instead, change `targetOwners` only.

## 3. Launch differences from Swift (all deliberate)

- No demo seeding in the RN launch. Swift seeds in DEBUG only; `--ccSeedNoTargets` only sets
  `onboardingPending`.
- `--ccFreshStart` wipes every user table and the two stored flags (Swift deletes the database files).
- Release `requiresSignIn` defaults to false, like Swift's TEMPORARY release behavior.
- `--ccForceOffline` is wired to `engine.setForcedOffline`, at launch and on a flag change.
- The sync triggers start once. `startDataBinding()` (U-33's file, untouched) is the only starter and
  `start()` of the controller is memoized, so StrictMode and repeated effects do not double it.

## 4. Account reset

`accountReset.ts` order: server deletion (errors caught) → session clear (caught) → stored flags
(`edSafeMode`, and `burnAddBackEnabled` which the Swift reset also removes) → ED-safe off → local rows →
widget placeholder → gate. `store.reset()` of the sync runtime clears only the sync tables, so
`deleteAllRows` deletes every user table (`sqlite_master`, not `sqlite_%`) in one transaction, after
stopping the engine. A failing local step does not announce a reset.

## 5. Not done here: process arguments, Sentry, PostHog

- Reading real launch arguments needs a native module: native slot (U-50). Until then
  `flagsFromArguments` is fed by tests and the console only.
- The telemetry seam imports no SDK; its default sink is a no-op. U-50 adds the Sentry and PostHog sinks.
  Allow-listed events are the two MetricKit ones; scrub drops photo, image, scan, health, hk, kcal,
  calorie, weight, meal, food, diary fragments in keys and in text values, recursively.
- The console's ED-safe switch sets the live mode only. The stored write belongs to U-41's Settings
  toggle (same `app_settings` key).

## 6. Pitfalls found

- RNTL v14: `render`, `fireEvent` and `act` are async. A synchronous call fails with "`render` function
  has not been called". `toHaveTextContent('x')` matches the whole text; use a regex for a substring.
- `jest.setup`'s secure-store reset did not clear the keychain in `rootRuntime.test.ts` (a session
  leaked in from another test). The test deletes `SESSION_STORAGE_KEY` itself in `beforeEach`. The root
  cause was not investigated.
- `app/onboarding/index.tsx` does not await `targets.saveTarget`. It works if writes queue FIFO on the
  single SQLite connection; the gate re-reads after the local-write notification, so a late write still
  lands. Worth an `await` in the next onboarding touch (U-31's file, not changed here).
- The `Stack.Protected` render in `_layout.tsx` is not Jest-run (it needs the Expo Router native stack);
  the route decision and the typed hrefs are. Typecheck covers the typed routes.
