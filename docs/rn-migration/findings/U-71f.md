## Why

The review of PR 45 found that "220 cals", "5 kilojoules" and "640kJs" passed the screen of U-71e: both of its regular expressions needed a word
boundary that these forms break. User text reaches the screen (the diary toast reads "<title> deleted", and a custom food may be called "220 cals"),
so the rule has to read the words as people write them.

## The rule

`carriesCalorieFigure(text)` (new module `apps/mobile/src/design/calorieFigure.ts`) is true when, read without case, the text holds one of
`kcal kcals cal cals calorie calories kJ kJs kilojoule kilojoules` as a word. The regex is

```
/(?:^|[^a-z])(?:kcals?|cals?|calories|calorie|kjs?|kilojoules?)(?![a-z])/i
```

A word is a run of those letters with no letter right before and no letter right after. A digit, a space, punctuation, a bracket or the edge of the
text next to it is fine, so "640kcal", "6CAL", "Cal 640", "kcal." and "calories," are hidden while calcium, December, escalate, scalable, Calzone and Calm
stay shown. It replaces the two regexes of U-71e (`\b…\b` and `\d\s*…\b`): one rule now, and the digit case is a special case of it.

- Moved out of `Toast.tsx` as the brief allowed. `Toast.tsx` re-exports `carriesCalorieFigure`, so `design/index.ts` (not touched) and every caller keep the same
  name and path. `FoodRow.tsx` imports it from the module instead of from `Toast.tsx`.
- No lookbehind and no `\p{L}`: the rule does not rely on engine support in Hermes. "Letter" is `a-z` only. A non-ASCII letter next to the word ("éCal") reads
  as a break, so it is hidden: the screen fails toward hiding.
- Accepted false positive, as in U-71e: a text that is only a name such as "Cal" is hidden. Also hidden: "Kj" alone, "Cal." and the like.
- Not in the brief's list, so shown: "kilocalorie", "kilocalories", "Kcalories" (letters on both sides of the listed word, a longer word). If the owner wants
  these hidden, add them to the alternation; one line.
