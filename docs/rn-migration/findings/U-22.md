# U-22 findings: design system (src/design)

Unit of `docs/rn-migration/plan.md`. Worker: Worker-G2. Branch `rn/u-22-design-system`.

## What was ported

- `apps/mobile/src/design/tokens.ts`: every token of `Tokens.swift` — `space` (CCSpace),
  `radius` (CCRadius), `size` (CCSize), `typography` (CCTypography roles → iOS system text style
  points and weights), `scaledNumberSize` (CCScaledNumber hero 56 / plan 64) and the 23 catalog
  colors for light and dark. `getTokens(scheme)` is pure; `useTokens()` reads `useColorScheme()`
  from react-native. `withAlpha(color, alpha)` is the `Color.opacity()` equivalent for #RRGGBB.
- `apps/mobile/src/design/edSafe.ts`: the single ED-safe API — `edSafeMode()`, `edSafeHidden()`,
  `setEdSafeMode()`, `useEdSafeMode()`, `useEdSafeHidden()` (module state + `useSyncExternalStore`,
  stable boolean snapshot per spike pitfall 13). Not persisted; U-51 persists it.
- 29 components under `apps/mobile/src/design/components/`, one per CC component, same name minus
  the `CC` prefix, plus `ScaledNumber` (CCScaledNumber lives in Tokens.swift). `index.ts` is the
  barrel. 119 Jest tests (33 suites) cover every variant and every ED-safe branch; the old
  `ComponentContractTests` cases are ported one Jest case per old test case (same behavior
  sentence).
- 71 SwiftUI snapshot PNGs copied verbatim to
  `docs/rn-migration/reference/swiftui-snapshots/` (`find … -name '*.png' | wc -l` = 71).

## Not ported, with reasons

- **CCTabBar** — per brief: NativeTabs (expo-router) renders the iOS 26 tab bar in the app shell;
  the `ViewModifier` + `UITabBarAppearance` port makes no sense on RN.
- **ScanFAB** (in Shell.swift) — belongs to the app shell, not to this unit (per brief).
- **High-contrast color variants** ("high", "dark/high" appearances in the colorsets) — React
  Native has no built-in increased-contrast trigger wired in this worktree; light and dark are
  ported. If a unit later needs it, read `AccessibilityInfo.isDarkerSystemColorsEnabled`-style
  support first.
- **CCChartDescriptor as an AX object** — RN has no `.accessibilityChartDescriptor`. The port is
  `makeChartDescriptor(points)` returning the descriptor DATA (title "Trend", "Date" categorical
  axis, "Value" numeric axis, one continuous series) + the chart's accessibility label built from
  the same data, so the VoiceOver contract (one series, one point per input) stays testable.
- **The 0.12s ease-out press animation of CCPrimaryButton** — approximated by the instant
  Pressable pressed state (scale 0.96). react-native-reanimated was not worth pulling for one
  120ms transform; the brief allows it but does not require it.
- **CCDashedAddButton's exact 6/4 dash pattern** — RN's `borderStyle: 'dashed'` cannot take a
  custom dash array; the dashed border shape is native.

## Pitfalls and docs that were wrong

1. **Dual React under jest-expo (the big one).** `apps/mobile` pins `react@19.3.0` exact, so npm
   nests it under `apps/mobile/node_modules`, while react-native's peer resolves to the hoisted
   root `react@19.3.1`. jest-expo's moduleNameMapper pins `^react-native($|/.*)` but **not**
   `^react$`. Result: app-side code got React 19.3.0, the RN test renderer ran on 19.3.1, and any
   app-side hook crashed with "Invalid hook call" / "Cannot read properties of null (reading
   'useSyncExternalStore')". Fix (test-only, in scope): every component test file starts with two
   `jest.mock` calls that re-point `react` and `react/jsx-runtime` onto the renderer's copy — the
   root path is computed inside the factory from `require.resolve('react-native')` (mapped to the
   hoisted RN), so it is portable and never hardcoded. Metro's production resolution is untouched.
   Every other JS unit with hooks will hit this; the preamble is copy-paste ready in any
   `src/design/**/**.test.tsx`.
2. **RNTL 14 + React 19 needs awaited interactions.** A sync `fireEvent(...)` after
   `await render(...)` reports "overlapping act() calls", leaves the act scope dirty, and the NEXT
   test in the file renders an empty tree ("Unable to find an element with testID"). All
   interactions here are `await userEvent.press(...)` or `await act(async () => fireEvent(...))`.
3. **`accessible` containers hide children from RNTL queries.** Components with
   `accessibilityElement(children: .ignore)` parity (`accessible` + label) hide their text children
   from `getByText`/`toHaveTextContent`. Text-presence assertions use
   `{ includeHiddenElements: true }`; the a11y contract is asserted through
   `toHaveProp('accessibilityLabel', …)`.
4. **`useColorScheme` under the RN jest preset** is a `jest.fn(() => 'light')`
   (`@react-native/jest-preset/jest/mocks/useColorScheme.js`) — cast once with
   `as jest.MockedFunction` and drive it with `mockReturnValue('dark')`. `Appearance.setColorScheme`
   does nothing in the jest environment (NativeAppearance is null there).
5. **Swift `.rounded()` ≠ `Math.round` on .5.** Swift rounds away from zero: `(-0.45).rounded()`
   scale → −0.5, while `Math.round(-4.5)` → −4. `kgValue` therefore rounds the magnitude and
   reapplies the sign. Watch this on every future kcal-parity port (half-up rule).
6. **`defaultDayProgress` divides milliseconds by 86,400,000** — the Swift version divides seconds
   by 86,400. Caught by the unit-interval test (12:00 noon came out as 500).
7. **`Colors.xcassets` values are hex strings** in Contents.json (`0x…` components); the test
   table lists the parsed light/dark hex per colorset.
8. **jest-expo handles tsconfig `paths`** — `@/*` from apps/mobile/tsconfig works in tests and
   typecheck; `src/design` uses relative imports anyway to stay portable.
