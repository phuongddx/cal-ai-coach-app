# U-10 findings — core domain port (packages/core)

Worker: Worker-G1. Unit of `docs/rn-migration/plan.md`. Every public type and function of the
nine Swift sources has a TypeScript counterpart; this file explains the merges, renames and
hand-offs the brief asks to be listed.

## 1. WidgetSnapshot vs the spike snapshot shape (the CO-05 reconciliation)

`WidgetSnapshot.swift` carries three fields: `caloriesRemaining: Int`, `edSafeMode: Bool`,
`updatedAt: Date`. The spike's widget props (`CaloriesWidgetProps` in
`apps/mobile/src/widgets/CaloriesWidget.tsx`, which `WidgetSnapshotPublisher.ts` aliases as its
`WidgetSnapshot`) carry nine: `date`, `consumedKcal`, `goalKcal`, `proteinG`, `carbsG`, `fatG`,
`proteinGoalG`, `carbsGoalG`, `fatGoalG`. Differences:

- Swift has no day key (`date`), no consumed/goal split, no macro figures — the spike invented
  them so the widget could render the Ember ring and macro bars.
- Swift has `edSafeMode` and `updatedAt` — the spike has neither.
- Swift `caloriesRemaining` is the published remaining figure (never below zero); the spike
  widget computes `max(0, goal − consumed)` itself from `goalKcal`/`consumedKcal`.

Resolution within this unit's writable scope: `packages/core/src/widgetSnapshot.ts` defines the
Swift type exactly, and `snapshotFromMeals.ts` now returns the spike props **plus** the three
Swift fields (`caloriesRemaining` via `kcalLeft`, `edSafeMode` as a new fourth parameter defaulting
to `false`, `updatedAt` as `now.toISOString()`). `SnapshotFromMeals = CaloriesWidgetProps &
WidgetSnapshot`. The callers outside this unit's scope (`binding.ts`, `spikeActions.ts`,
`WidgetSnapshotPublisher.ts`, whose `buildTimeline` writes `date`/`consumedKcal`/macro fields on
rollover) keep type-checking unchanged, so the root gates stay green.

**Hand-off to U-43** (owner of the widget/store wiring): flip `CaloriesWidgetProps` to the Swift
shape, move `buildTimeline`'s rollover to it, point `binding.ts`/`spikeActions.ts` at the new
props, and decide the App Group payload encoding (this port serializes `updatedAt` as an ISO-8601
string; Swift's `JSONEncoder` default would emit a `Date`). The data is already in every
published snapshot, so the flip is a type change, not a data change.

## 2. WidgetSnapshotStore — the App Group file layer is U-43

The Swift store reads/writes the App Group container file (`widget-snapshot.json`) through
`FileManager`. Core must stay pure (invariant I13), so `WidgetSnapshotStore` takes an injectable
`WidgetSnapshotContainer` (`read`/`write`/`remove` over the JSON text) and `null` models the
"container unavailable" path. The silent-no-op contract is ported and tested; U-43 wires the real
App Group file (or the expo-widgets channel) behind that seam.

## 3. SyncEnvelope — shapes stay in api-contract, rules came here

The zod schemas in `packages/api-contract/src/sync.ts` are the RN wire contract and are NOT
duplicated (and zod never enters `packages/core`). Ported as pure functions over structural types
in `syncEnvelope.ts`: `rejectUnknownKeys`, `decodeDiaryEntrySnapshot` (the Swift
`DiaryEntrySnapshot.init(from:)` logic), `createPushRequest` (non-empty, unique opIds),
`validateAcknowledgementSet`, `validatePullResponse` (cursor rules),
`parseSyncDate`/`formatSyncDate`, and the `SyncTransport` interface. Notes:

- The RN wire contract is meal-based (`MealSchema`/`MealRecordSchema`) while the Swift envelope is
  `diary_entries`-snapshot-based; the validators are deliberately structural (they only need
  `opId` / `snapshot.serverVersion` fields) so the sync engine (U-20+) can apply them to either
  shape.
- Swift's `PushAcknowledgement` guard `serverVersion >= 0` is a decode-side rule; the RN contract
  already enforces version floors in zod (`serverVersion: min(1)`), so it is not re-implemented
  here.
- Swift throws `DecodingError.dataCorrupted`; the port throws `SyncEnvelopeError` with the same
  sentences.
- `CanonicalRowVersion` is declared in Swift's SyncEnvelope.swift; in TypeScript it lives in
  `canonicalVersion.ts` (next to the comparator that is its only consumer). `acceptedOpId`
  compares on the canonical uppercase form, matching Swift's `uuidString`.

## 4. NotificationScheduler — what is NOT core, for U-42 to wire

Ported: the pure `pendingRequests` rule (which of `meal.lunch`/`meal.dinner`/`eod.recap` is
pending, with copy and repeating calendar triggers at 12:30/18:30/21:00, ED-Safe recap body with
no digits). Not ported (Swift `refresh()`, the UNUserNotificationCenter side), listed for U-42:

- `center.requestAuthorization(options: [.alert, .sound, .badge])` — lazily, on the first
  scheduling attempt, never at launch.
- `center.removePendingNotificationRequests(withIdentifiers: allIdentifiers)` then `center.add`
  per request — idempotent replace, at most 3 pending, never additive.
- `refresh()` is called from the write/foreground seam (`AppEnvironment.notifyLocalMutation()`
  equivalent) — never a second observer.
- `expo-notifications` counterpart: schedule calendar/weekly trigger notifications with the same
  identifiers, remove-and-replace on every refresh.

`pendingRequests` ignores `now` in Swift (the triggers are repeating wall-clock times); the port
keeps the parameter for signature parity and ignores it the same way.

## 5. Time zones: the Jest worker resolves ICU's zone at spawn

The brief's prescribed `process.env.TZ` writes in `beforeAll` are inert in this setup: plain Node
26 re-resolves `TZ` at runtime, but Jest workers (worker threads) resolve V8/ICU's default zone
once at spawn and ignore later env writes (probe: env shows `America/Los_Angeles`, `Date` still
formats `+07:00`). Changes made:

- `packages/core/src/dayKey.ts` takes an explicit IANA `timeZone` argument — the direct
  counterpart of Swift's `calendar:` parameter (the time-zone carrier) — defaulting to the
  process zone. The three-zone coverage runs through that argument.
- `packages/core/jest.config.js` pins `process.env.TZ = 'UTC'` before workers spawn, so the
  StreakEngine suite's UTC fixture is real and the whole package suite is machine-independent.
- The per-block `beforeAll`/`afterAll` env writes from the brief are kept (harmless, and correct
  on runtimes that re-resolve).

## 6. ProofRecord port notes

- Swift's `ProofValue` enum with associated values is the discriminated union
  `{ kind: 'string' | 'int' | 'double' | 'bool' | 'uuid' | 'date' | 'array' | 'dictionary', value }`
  (the brief's shape rule). UUIDs serialize on the uppercase canonical form (Swift
  `uuidString`); dates as ISO-8601 with the process-zone offset (Swift
  `ISO8601DateFormatter.string(from:timeZone: .current)`); output is sorted-keys JSON (Swift
  `.sortedKeys`; `.withoutEscapingSlashes` needs no equivalent — JS never escapes `/`).
- The sensitive-key regex is the same pattern: `/(password|secret|token|apikey|authorization)/i`.
  The legacy identity literals are built by joining parts at runtime, in the serializer and in
  the test, so the tokens never appear in source.
- `ProofRecordSerializer.data` returns the bytes as a UTF-8 string (Swift's `Data`).
- The validator round-trip twin pipes the sample through stdin to
  `scripts/measure-phase1-sync.mjs` (the script's own input contract) instead of Swift's temp
  file; exit 0 and a `PASS` line are asserted.

## 7. StreakBadgeInsightTests — nothing pure to port

The brief says to port the pure cases of `native/App/CoachCalTests/StreakBadgeInsightTests.swift`
that test `StreakEngine` alone. Reading the file in full: its six tests all drive the GRDB
database, `ProgressModel`, `CoachModel` or the DesignSystem component; none exercises
`StreakEngine` in isolation. Nothing ports from it; the engine behaviors it touches are already
covered by the StreakEngineTests twins.

## 8. KcalArithmetic and the server rule

`KcalArithmetic.mealKcal`/`macroGrams` are formula-identical to the server's
`arithmetic.ts` `roundKcal`/`roundMacro` (Math.round half-up on positives). The agreement test
decomposes the Swift golden vector (145 kcal/100 g at 320 g → 464) into per-100 g macros
(20 P / 10 C / 25 fat kcal), scales them through `macroGrams`, and proves `kcalFromMacros` over
the current grams returns the server figure — invariant I6's core-side proof.
