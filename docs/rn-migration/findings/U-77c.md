# U-77c findings — Sign-in: the code step on the frames of round 4

Worker: Worker-S1. Parity row AU-01. Stage A (JS and Jest only). Stage B (Simulator evidence) has not run: no slot was given.

The behavior does not change: `requestCode(email)` once per tap on "Send code" or "Resend code", `verifyCode(email, code)` on "Verify", nothing submits when the sixth digit lands, `onSignedIn` once with the stored session. The screen is now three steps of one route: entry (frames 61, 62), e-mail (108 to 111), code (112 to 115).

## Design changes

- **E-mail step** (`EmailStep.tsx`, frame 108/109): Back glass button (`auth.emailBack`), title "Continue with email" (`type.title1`), subtitle "We'll email you a 6-digit code. If you're new, the same code creates your account." (`type.body`, `text2`), the field on `FillField` `variant="text"` with its keyboard props (`auth.emailField`, `.label`, `.ring`; placeholder "Email"), the error line under the field, and "Send code" (`auth.sendCode`) docked. Disabled while the address is empty or the form is busy.
- **Code step** (`CodeStep.tsx`, frame 112/113): Back (`auth.emailBack`), title "Enter the code", "We sent a 6-digit code to **address**." (`auth.codeSent`, the address in `type.headline`), the six cells of `CodeField` inside `auth.codeCells` over the hidden input `auth.otpField` (label "6-digit code", `autoFocus`), the error line, "Can't find it? Look in Junk or Promotions." (`type.subheadline`, `text2`). Dock: "Verify" (`auth.verifyCode`, enabled at six digits and not busy), "Resend code in m:ss" (`auth.resendCode`) and "Use a different email" (`auth.useDifferentEmail`).
- **Shared frame** (`StepFrame.tsx`): Back row, title block, scrolling body, dock above the home indicator, keyboard avoidance.
- **Resend cooldown** (`useResendCountdown.ts`): 60 seconds counted by the client from the moment `requestCode` answered. The clock is the `now` prop of `SignInScreen` (default `Date.now`); tests inject it and advance jest fake timers. At zero the button reads "Resend code" and asks for a new code with the same address, and the 60 seconds start again. When the server refuses a resend (429 and the like), the line says so and the button stays at zero.
- **Errors** (`authCopy.ts`), both `accessibilityRole="alert"` through `ErrorLine`:
  - `requestCode` rejected (`invalidInput`, envelope `VALIDATION_ERROR` or `UPSTREAM_ERROR`): the field border in error and "We couldn't send the code. Check the address and try again." A resend that is refused shows this line without red cells.
  - `verifyCode` answered 401 (`envelope` `UNAUTHORIZED`): the six cells in error, the digits kept, and "That code is wrong or has expired. Check the latest email, or send a new code."
  - Any other error (network, `invalidResponse`, a 429 on verify, Apple, Google) keeps the message of `authErrorMessage`, with no red border.
  - Typing in the field or the cells clears the error and its border; a step change clears it.
- **Entry step** (`EntryStep.tsx`): "Continue with email" takes the leading `mail` icon of `SecondaryButton`. The three literals of PR 47 are text styles now: the label and the address (`type.headline`/`type.footnote` through `textStyle()`), and "or" (`type.footnote`).
- **Design system**: `CodeField` gains `autoFocus?: boolean` (default false) and its tests. Nothing else under `design/` changed.
- Greps (run before the commit): `useEdSafeHidden(|edSafeHidden(|edSafeMode(` prints nothing; `#[0-9A-Fa-f]{6}` prints nothing under `features/auth`; no literal `fontSize`/`fontWeight`/`lineHeight` number outside the tests.

## Needs a design component

1. `FillField` has no `autoFocus`. Frame 108 draws the e-mail field focused with the keyboard up; the field does not take the focus on its own. (`CodeField` got `autoFocus` here, as the brief allowed.)
2. The Google mark ("G") has no icon; the Google button stays text only (a recorded deviation from U-77b).
3. `SecondaryButton` radius is 18 (`radius.btn`); the frames show 14.
4. The glass Back button and the centered header row of frames 108 and 112 are drawn from `GlassIconButton` and `Text`; `SheetHeader` names its back button `<testID>.back`, the required identifier is `auth.emailBack`.

## Deviations

- **"Resend code" at zero.** The brief says "Resend code"; `FRAMES.md` and frame 114 say "Send a new code". The brief won; the app uses "Resend code" in both states.
- **Address weight.** The frame draws the address in bold 700; the token the brief names is `type.headline` (600). 600 is used, to stay on a token.
- **"or" weight.** The U-77b literal was 13/500; `type.footnote` is 13/400. The token won.
- **Field height.** `FillField` text variant is 56 pt; the frame draws 52 pt.
- **No autofocus on the e-mail field** (see "Needs a design component", 1).
- **Error border color** is `colors.error` on the field and on the cells (the frames' red), the error line is in `errorInk`.
- **A 429 on verify** keeps the generic `authErrorMessage`: the wrong-code line would say something the app does not know.
- **Not built, as before:** the "Sign in | Create account" segment, "Forgot password?", the reset-link screen, the back button of the entry step, the lock line about training models, the Terms footnote, the Google G mark.

Kept: `auth.form`, `auth.signInApple`, `auth.signInGoogle`, `auth.signInEmail`, `auth.emailBack`, `auth.codeSent`, `auth.tile`, `auth.emailField`, `auth.sendCode`, `auth.otpField`, `auth.verifyCode`.
