# U-61b findings — the Ember frame catalog

Docs-only unit: `docs/design/ember/FRAMES.md` and this file; no code changed. Branch
`rn/u-61b-frames` from `origin/main` @ `43ba369`.

## 1. The frame count: 40, not 35

The brief and the done-when say "28 phone screens and 7 glanceables". The canvas holds 35 app
frames **plus 5 app-icon frames** in the `#icon` band, and the acceptance says the listed count
must match the `figure.frame` count of `index.html`. Measured with the canvas open in a browser:

```sh
document.querySelectorAll('figure.frame').length   # → 40
# by section: scan 6, core 6, profile 4, billing 3, onboarding 9, glance 7, icon 5
grep -c '<figure class="frame"' docs/design/ember/index.html   # → 19 static
grep -c '<figure class="frame"' docs/design/ember/screens.js   # → 11 template occurrences
#   rendering 21 runtime frames (9 onboarding + 7 glanceables + 5 icon)
```

Decision taken: FRAMES.md gives all 40 a section — the 28 + 7 app frames each with the seven
parts, plus the 5 icon frames (also with the seven parts; they are reference for the icon build,
which D13 and PL-17 keep out of the app until the layers exist). The count in the document
therefore matches the acceptance command exactly.

## 2. The plan's three follow-ups: confirmed

- **Analyzing with server stages** — confirmed as a backend follow-up. The scan API answers in one
  request; today's RN screen advances its three steps on a 0.5 s dwell timer with a fourth step
  after the 5 s watchdog (`parity-detail/scan.md` SC-03). The frame forbids the timer.
- **Haptics** — confirmed. `grep -c expo-haptics package.json apps/mobile/package.json` → 0 in
  both; needs the next native unit.
- **Billing** — confirmed, with one correction: the **quota sheet's** limit and reset day are
  already available client-side, because the 402 envelope carries the typed entitlement
  `{tier, scansUsed, scanLimit, windowResetAt}` (`packages/api-contract/src/index.test.ts`, BE-08
  done). U-77 formats that state; no new endpoint is needed for the sheet. The real gaps are
  StoreKit products + configuration + a purchase SDK (paywall prices, Change plan, in-app cancel,
  Restore, Billing history — PL-16: no IAP code anywhere).

## 4. Identifier mismatches found while grepping (input for the restyle units)

Section 4 of every frame lists both sides. The notable one-sided or renamed strings:

- Today: the RN screen uses `ember:*` testIDs (`ember:ring`, `ember:kcal-left`, …) where the Swift
  screen used `today.*` (`today.ring`, `today.weekStrip`, `today.dayCell`, `today.dateSelector`,
  `today.foodRow`, `today.recentMeals`, `today.emptyState`, `today.streakCard`,
  `today.startSetup`) and `offline.badge` (RN DS: `offline-badge`). The evidence harness addresses
  the RN strings, so the restyle keeps them and records the mapping; U-76 owns this screen.
- RN-only: `scan.checklist`, `scan.barcodePicker`, `scan.fixtureFeed` (test helper),
  `water-droplet-ring` (test helper on an a11y-hidden ring), `settings.cancelDelete` (RN-added,
  the Swift confirmation dialog had no cancel identifier).
- Swift-only: `scan.describe.done` (RN: `scan.describeSubmit` + `scan.describeField`), the
  `scan.modePill` group identifier, `profile.stat.dailyTarget/.daysLogged/.weight`,
  `diary.previousDay` / `diary.nextDay`, the DEBUG-only `debug.toggleOffline` (not ported; the
  offline override has no RN counterpart).
- Design-system strings riding on screens (unchanged): `ccstepper.decrement` /
  `ccstepper.increment`, `confidence-badge`(:compact), `toast` / `toast:undo`, `warning-chip`,
  `chart-card`, `streak-card`, `search-field`, `offline-badge`, plus the templated DS ids
  (`food-row:<title>`, `option-card:<title>`, `wheel-field:<label>`, …).
- Handoff note 3 names `scan.grams.<id>.field` for the new typed field beside the kept
  `scan.grams.<id>.increment`; today only the wrapper `scan.grams.<id>` exists
  (`ReviewSheetView.tsx:166`, Swift `ReviewSheetView.swift:192`).

## 5. Copy tension between the frames and the locked strings

The onboarding frames draw new hero/step copy ("Snap your plate. See the estimate and how sure we
are.", "What brings you here?", three activity cards, six diet chips, no DOB wheel on step 3).
OB-01 locks the copy and the contract tests assert it; rule 22 says a restyle does not change test
sentences. FRAMES.md records per step: restyle the stage, keep the locked strings, and route any
copy/vocabulary change (the "Prefer not to say" engine path, the 3-activity/6-chip vocabulary) to
the owner. The same applies to Review's "Fix Issue" → "Something wrong? Report it": the identifier
`scan.fixIssue.<id>` survives, the label changes.
