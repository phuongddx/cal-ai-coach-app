Date 2026-11-27. Branch `rn/u-13-native-foundation`. Simulator iPhone 17 Pro, iOS 26.4.

## Result

`coachcal`, App Group `group.com.nextlabs.coachcal`, widget extension `com.nextlabs.coachcal.CoachCalWidget`).
Build: 1002 s from cold DerivedData, `Build Succeeded`, 0 errors, 2 warnings. Evidence:
`evidence/U-13/build-log-tail.txt`, `evidence/PL-17/first-launch.png`, `evidence/PL-15/compliance-output.txt`.

## Findings for later units

1. **Widget snapshot.** `expo-widgets` writes the group from the `groupIdentifier` option to both entitlements
   and to Info.plist `ExpoWidgetsAppGroupIdentifier`. Because it equals the production group, the widget reads
   what the app writes through the App Group. U-43 should still prove it on a device.
2. **HealthKit background delivery.** The HealthKit plugin's default adds the background-delivery entitlement
   on its own in some versions; the local plugin sets it explicitly so the result does not depend on that.
3. **Photo library string.** The generated Info.plist has `NSPhotoLibraryUsageDescription = "Allow $(PRODUCT_NAME)
   to access your photos"` (a default added by an Expo module). The SwiftUI app had no such string. The
   owner of the scan unit should either set a CoachCal-specific string or remove the permission, because the
   App Store review reads it.
4. **Local network string.** `NSLocalNetworkUsageDescription` and `NSBonjourServices` come from expo-dev-client
   and are stripped by the "Strip Local Network Keys for Release" phase in Release builds. Not checked in a
   Release build yet.
5. **Icon.** The icon is RGBA; App Store Connect requires no alpha channel on the 1024 marketing icon. Flatten
   it before the first upload (U-61).
6. **Simulator entitlements.** See `build-recipe.md` pitfall 5: `codesign` shows an empty set on a simulator build.
7. **Tests live in `src/__tests__/`**, never under `src/app/` (every file there is a route, and a test file
   would become a screen). `routes.test.tsx` asserts that.
8. **Build warning.** Xcode prints "The @ExpoModule class 'CoreModule' is internal" from
   expo-modules-core; it comes from node_modules and was not patched.

## Deliberately not added

No plugin for expo-image-picker, expo-image-manipulator, expo-web-browser, expo-sharing and expo-secure-store:
they need no Info.plist key or entitlement beyond what is already set. Android is out of scope for this
migration (decision of the owner, 2026-11-27).
