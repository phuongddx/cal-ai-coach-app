## 3. Pitfalls found while writing

- The parity gate does not check `crypto.randomUUID`, which is easy to assume: no gate checks it
  (spec invariant I11 is a convention). Nothing under `apps/mobile` uses `crypto.randomUUID`, which is
  what the rule needs; `apps/api` uses it in production code (`scan/pipeline.ts`, one id per persisted
  scan item) and in `testing/sqlHarness.ts`, and `scripts/rn/e2e-sync-app.sh` uses it too.
  `AGENTS.md` says so.
- `zustand` and `@tanstack/react-query` are dependencies of `apps/mobile` (decision D3) but no app
  code imports them; only `src/__tests__/nativeModulesSmoke.test.ts` does. `AGENTS.md` says so
  instead of describing them as the state layer.
- The webhook goes through `webhook_apply`, not `apply_webhook_event` (the Supabase name). The
  invariants paragraph names the real function.
- `parity-check.mjs` guards the inventory comparison with `existsSync(native)`, so with `native/`
  gone it skips the "file not inventoried / no longer exists" loops; `swift-inventory.tsv` still maps
  every old path to a parity row and that mapping is still checked. The gate result on the pushed head
  is in the pull request body.
- `npm ci` was not run for real (it replaces the cloned `node_modules`); `npm ci --dry-run` was.
