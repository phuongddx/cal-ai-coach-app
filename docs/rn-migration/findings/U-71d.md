## 2. Deviations from the frames, and judgment calls

| Item | Decision | Why |
|---|---|---|
| `OptionCard` border | stays `accentStrong` | see above |
| `TrendChart` date labels | spaced with `space-between` over the chart width, at evenly spaced point indexes | when the points are not evenly spaced in time, a label can sit a little off its point; the frame has evenly spaced days. No measurement of the rendered width was possible without a Simulator. |
| `Toast.message` rule | hidden only when it carries a calorie figure, under ED-safe | the owner asked for "a line that holds kcal stays hidden"; the detector is a regex (kcal/calories/kJ word, or a number before cal / kcal / calories / kJ), so a line that writes a figure in another way ("about 420") would show. Callers should not put a figure there. |
| `ringCompact` and its stroke | follow `--ring-sm` / `--ring-sm-stroke` (120 and **12**) | see section 3: the stroke moves from 8 to 12 |

## 3. Tokens (item 7)

`emberTokens.generated.ts` (from the owner's sync) holds the new groups. Done here:

- **The token test covers every variable of tokens.css**, not only colors: `__tests__/tokens.test.ts` (now 41 tests) compares
  `tokens.css` -> `tokens.json` -> `emberTokens.generated.ts` -> `tokens.ts` for the colors in four modes, `space`, `radius`,
  `size` (all 11 variables: `tap, btn, shutter, ring, ring-stroke, fab, ring-md, ring-md-stroke, ring-sm, ring-sm-stroke,
  macro-bar`), `radius.btn`, **`type`** (the sixteen `--t-*` parsed as `weight size/line var(--cc-font[-round])`: size, line height,
  weight, family) and **`typeVar`** (the variable that names each style), and `appleHealth`, `emberTile`, `mediaScrimStrong`

### Visible effect on screens that do not change in this unit

`size.fab` 56 -> 62 moves the floating scan button on Today (`features/today/ScanFab.tsx`) and the Today bottom padding
(`todayBottomPadding` reads `size.fab`); `size.ringCompactStroke` 8 -> 12 thickens the compact `CalorieRing` and the ring of
`features/onboarding/GeneratingPlanScreen.tsx`; the 600 -> 700 weight of `title` and `heading` makes every unrestyled screen title bolder.
All three are the design's own values (tokens.css), not choices of this unit. The `todayBottomPadding` test in
`features/today/__tests__/TodayView.test.tsx` pinned `56` literally: see "Findings for the owner" below.

## 4. Findings for the owner

1. **Rules in conflict, decided by me, revert is one commit.** The brief says `size.fab` follows the chain (`--fab` is 62), `npm test` must be green, and nothing under `features` changes. `features/today/__tests__/TodayView.test.tsx` pinned `FAB_BOTTOM_PADDING + 56 + 48` and failed with `Expected: 132, Received: 138`. I changed the two literals `56` to `62` (comment: `--fab` of tokens.css) in a separate commit, `test(rn): follow the 62 pt fab of the design in the TodayView padding test`. No sibling branch (`rn/u-72` to `u-77`) touches `features/today`, so there is no conflict to expect. If the owner wants the scope rule to win, drop that commit and keep `fab: 56` in `tokensWithoutSource.ts` instead (the token test then has to skip `fab` in link 3).
2. `ringMd` (150 / 13) exists in the chain and is exposed (`size.ringMd`, `size.ringMdStroke`) but `CalorieRing` has no variant that
   uses it (its variants are hero 184, compact 120, goal 56). Adding a variant is a component change this unit did not make; Today's ember card on frame 07 (150 pt ring) will need it.
3. `ringGoal` (56 / 6) has no variable in tokens.css. Adding `--ring-xs` and `--ring-xs-stroke` there would empty the register of sizes.
4. `hero` 56 and `planNumber` 64 of `ScaledNumber` have no `--t-*` style (the largest is `--t-num-xl`, 44). Either Designer adds two styles or the screens move to `numXl`.
5. The frames draw the selected `OptionCard` border in `accent`; the component keeps `accentStrong` (section 2).
