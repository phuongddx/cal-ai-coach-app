## 1. How the counts were made

The Swift tree still lives at `main` @ `00baa0d`, so the worktree holds both sides (`native/` and
`apps/`, `packages/`). Every number below comes from commands run in the worktree.

File counts (the brief says 29 + 17; found exactly that, and no other `*Tests*.swift` under
`native/` outside `CoachCalUITests/`):

```sh

find packages/core/src packages/api-contract/src apps/api/src apps/mobile/src \
  \( -name '*.test.ts' -o -name '*.test.tsx' \) | grep -v node_modules | sort   # 151 files
```

Case counts, per file (the brief's `grep -c "@Test\|func test"` and
`grep -c "^\s*\(it\|test\)("` do not run on macOS BSD grep — it has no `\|` alternation in BRE and
no `\s`; the equivalent I ran is quoted so the numbers are reproducible):

```sh
grep -cE '@Test|func test' <swift-file>          # 229 cases over the 46 files
grep -cE '^[[:space:]]*(it|test)\(' <jest-file>  # 1,004 cases over the 151 files
```

Representative output (Swift side; every file was counted the same way):

```text

 8 DomainRepositoryTests.swift 8 LiveApiClientTests.swift   8 ScanKcalParityTests.swift
 7 NotificationSchedulerTests.swift 7 SyncEngineDispatchTests.swift 10 SettingsTests.swift
13 DiaryWaterExerciseTests.swift  9 EdSafeSweepSnapshotTests.swift   5 WidgetSnapshotSnapshotTests.swift
```

Sentence matching was mechanical first, hand-checked second. A small Node script (kept outside the
repo, in the session temp dir) extracted every `@Test`/`func test*` name and every Jest
`it(`/`test(` sentence, normalized camelCase to words (`mealKcal` → "meal kcal"), and matched
Swift case → Jest sentence by (1) exact normalized equality, then (2) token overlap ≥ 0.7
(reworded). A second pass matched the NO-MATCH files against the union of all 1,004 Jest cases, so
files whose twins are spread over many Jest files (the design contract) were not lost by picking a
single best file. The unit that wrote each twin came from the first commit that added the Jest
file:

```sh
git log --diff-filter=A --format='%h|%s' -- <jest-file> | tail -1
```

mapped to units via the wave records in `docs/rn-migration/plan.md` (PR 11 = U-20, PR 12 = U-12,
PR 14 = U-21, PR 16 = U-30, PR 17 = U-23, PR 18 = U-32, PR 19 = U-31, PR 24 = U-40; the wave-1
core/backend/design commits carry their unit in the branch content, confirmed against
`parity-detail/*.md`).

The five-rows-per-detail-file spot check (11 files × 5 rows = 55 claims) verified that the quoted
Jest case sentence exists verbatim in the named file and that the named Swift source carries the
behavior. Result: all 55 hold. Two wording notes came out of it:

- `parity-detail/scan.md` (SC-02) names the proof `testFixtureCaptureSeamAlwaysReportsAccessGranted`
  under `scanCapture.ts`; the Swift case lives in `ScanCapturePermissionTests.swift:13` and its

  touches the camera, line 41–42). Behavior holds; the file pointer in the detail is off.
- `findings/U-32.md` §3 (the wave-3 follow-up assigned to U-60): verified in the Swift source —

## 2. What the counts cannot see

1. **Parameterized Swift tests count as one.** `@Test(arguments: [...])` runs N cases but occupies
   one line; `grep -cE '@Test|func test'` undercounts the runner's case count. Files that use it:
   SeedDataManagerTests, DomainMigrationTests, MigrationTests, CSVExportServiceTests,
   StreakBadgeInsightTests. The true executed-case total is somewhat above 229.
2. **Jest `.each` and `describe` structure are invisible** to the line count in the same way; the
   1,004 is `it(`/`test(` occurrences, not runner executions.
3. **"Reworded" is a judgment with a threshold.** Token overlap ≥ 0.7 accepts real rewordings and
   can miss a twin whose wording drifted far. Every NO-MATCH verdict in the table was then
   hand-verified against the union pass and, for the four files with no twin at all, against
   keyword greps (`clamp`, `granted`, `kcal`, `ED-safe`, `HealthKit`) across all 151 Jest files.
   The four "none" verdicts (Settings, HealthKit, MetricKit, design smoke) held.
4. **Exact-normalized equality is stricter than rule 9 needs.** `goldenParityAtFixtureGrams` kept
   verbatim as a Jest sentence counts as exact; a case renamed "golden parity at fixture grams"
   counts as reworded. The 99/86 split is therefore a lower bound on verbatim twins, not a
   quality verdict.
5. **Counts say nothing about assertions.** A twin with the same sentence can assert less. The
   spot checks (55 rows) and the detail files are the evidence for assertion depth; this audit
   did not re-read all 46 Swift bodies line by line (out of scope for the timebox).
6. **The Swift counts include the 5 module-smoke cases** (`moduleNameIsExposed`) — real cases, but
   they measure module wiring, not behavior. Four of the five have Jest twins; the design system's
   does not.
7. **`--cc*` fixture flags and clock injection differ between sides**, so a green twin does not
   prove the same fixture data flowed through it (the DiaryWaterExercise seed difference in §1 is
   exactly this class of difference).
