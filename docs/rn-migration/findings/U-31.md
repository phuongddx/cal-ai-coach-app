# U-31 findings — onboarding

Worker: Worker-G1. Unit of `docs/rn-migration/plan.md`. Ports the nine-step
onboarding of `native/App/Features/Onboarding/` (1,437 Swift lines) to
`apps/mobile/src/features/onboarding` and the `src/app/onboarding` route: the
`OnboardingModel` state machine over `TargetsEngine`, nine props-driven
screens, the Jest twin of `OnboardingContractTests` (8 sentences) plus the
brief-required extras, and one RNTL test per step.

## 1. The React seam of the `@Observable` model

Swift's `@Observable` re-renders on any field mutation; the RN model instead
bumps a `revision` counter and exposes `subscribe` / `getRevision`, and every
screen calls `useOnboardingModel(model)` (`useSyncExternalStore`) before
reading fields directly — the closest counterpart without proxies. Mutations
that Swift wrote straight onto the draft therefore became explicit methods
that end in `touch()`: `selectActivityLevel`, `setHeightCm`, `setWeightKg`,
`setBirthYear`, `setGoalWeightKg`. `selectGoal` / `selectSex` / `setPace` /
`selectDietStyle` are the ported originals. Both files keep the Swift names
where behavior is identical, so the parity table reads 1:1.

## 2. Generation without `Task.sleep`

`runGeneration` ports the 2-second minimum window (0.5 s per step, percent
25/50/75/100) over a `setTimeout` promise; `disableAnimations` skips the
window entirely and lands the reveal synchronously, like the Swift flag path.
`dispose()` cancels the pending timer (the flow view calls it on unmount —
the `Task.cancel()` of `deinit`), and `beginGeneration` is re-entry guarded by
a `generationStarted` flag instead of `generationTask == nil`.

## 3. No slider package: a core-RN `PaceSlider`

`@react-native-community/slider` is not in the dependency set (standing order
4: no new packages), so the Swift `Slider` (0…1.5, step 0.05) is a feature-local
control in `PaceSlider.tsx`: responder-driven track for real usage plus
`adjustable` accessibility actions (increment/decrement by the step). Every
change funnels through `model.setPace`, so the engine-owned clamp still snaps
the value back — the contract twin asserts 1.5 lands on 0.45 exactly like the
Swift case. Adding the community package later would be a drop-in swap.

## 4. RNTL v14 queries mirror the accessibility tree (test-visible only)

Two Swift caption rows are `.accessibilityHidden(true)`: the goal-weight pace
axis captions (Slow / Recommended / Fast) and the projection "Today … N
weeks" row. In RNTL v14, `getByText`/`getByTestId`/`getByRole` all walk the
accessibility tree, so an `accessibilityElementsHidden` element is
unqueryable (probe: a plain `<Text>` under a hidden View matches nothing,
testID included). Both rows are ported WITHOUT the hiding flag so their
locked copy stays assertable — a deliberate, documented a11y parity gap. A
later native-a11y sweep can re-hide them once a hidden-text query strategy
exists. Everything else keeps its Swift accessibility semantics.

## 5. Plan reveal's ED-safe hide is not portable yet (known gap, OB-09)

The Swift `PlanRevealView` collapses the kcal hero and the weekly-range line
via `.edSafeHidden()`. Invariant I7 (spec §3) forbids any `edSafe` call under
`features/` — the policy belongs to design-system components — but no DS
component owns a generic "collapse this surface" branch yet (`edSafe.ts`
exports only the flag API; the five kcal-aware DS components carry their own
branches). Editing `src/design` is out of this unit's scope, so both surfaces
render unconditionally and the gap is recorded here and in the parity detail.
The value hero's ED-safe line is locked copy (title/subtitle strings), not a
policy branch — that part ports cleanly.

Consequence worth noting for the owner: the acceptance grep
`grep -rn "edSafe" apps/mobile/src/features/onboarding` prints nothing — the
copy field names were deliberately chosen as `safeModeTitle`/`safeModeSubtitle`
even though the Swift members are `edSafeTitle`/`edSafeSubtitle` (values stay
verbatim). One comment references the Swift test name
`testValueHeroShowsHeroCopyAndEdSafeLine`; the exact-case grep still returns
nothing.

## 6. Route and finish

`src/app/onboarding/index.tsx` replaces the OB-01 placeholder. It is the only
file importing `getDataEnvironment`, `getSessionStore`, `getDebugFlags`,
`notifyLocalMutation` (plus `DEMO_USER_ID` and `requestHealthAccess`); the
model takes `ownerId`, `now`, `disableAnimations`, `saveTarget`, `notify` and
the HealthKit ask through `createOnboardingModel`. There is no onboarding
flag to write: like the Swift app, the finish gate is "a target exists"
(U-51 ports it on `targets.activeTarget()`), so `persistAndFinish` saves,
calls `notify`, and the flow hands off to `router.replace('/')` — the typed
route of the Today tab, same route the sign-in flow uses.

## 7. Small ports worth recording

- `healthAccess.ts` wraps `requestAuthorization` from
  `@kingstinct/react-native-healthkit` 16.2.0 (typings read first: it takes
  `{ toShare, toRead }` sample-type strings and resolves a boolean). The
  injected model dep returns `'granted' | 'denied'`; any thrown error maps to
  a denial so the screen shows its footnote instead of breaking the flow.
- The weekly range renders with a hand-rolled `grouped()` (comma grouping,
  Hermes-safe — no `Intl` assumption), matching the Swift `en_US`
  NumberFormatter: 1693 → "11,601 – 12,101 calories".
- The projection chart draws the Swift Charts composition (shaded band,
  nominal line, endpoint dots, horizontal gridlines) with `react-native-svg`,
  as the DS ChartCard does. Numeric axis labels of the Swift automatic axes
  are not ported (the chart sits between the start/goal header and the
  "Today / 12 weeks" caption, which carry the same numbers).
- The goal picker / activity cards reuse the DS `OptionCard`, whose a11y
  label format is `"<title>, <subtitle>, selected|not selected"`; the screen
  tests assert selection state through those labels.
- Screens wrap DS buttons in `<View testID=…>` because the DS button props
  carry no `testID` (the shipped sign-in screen's convention); RNTL presses
  go through the button role, XCUITest identifiers stay as testIDs.

## 8. Test mapping

  (same behavior sentences, ViewInspector cases render the screens) + brief
  extras: step order over `ONBOARDING_STEPS`, granted/denied HealthKit paths,
  `persistAndFinish` success/failure wiring.
- One RNTL file per step (`ValueHeroScreen.test.tsx` … `PlanRevealScreen.test.tsx`)
