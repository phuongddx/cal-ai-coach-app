## Findings and pitfalls

1. **Maestro `launchApp` arguments are a key-value map**, not a list, and on iOS they land as
   `-key value` pairs — the `--cc*` parser of `apps/mobile/src/debug/launchArgs.ts` (bare flags,
   value in the NEXT argument, double dash) would never see them. The flows that need launch
   arguments are therefore launched by the workflow with
   `xcrun simctl launch <udid> com.nextlabs.coachcal --ccScanScenario 200` /
   `--ccEDSafe` — exactly the way `scripts/rn/evidence/lib.sh` `app_open` does it — and the
   flow itself only `openLink`s the dev-client URL (`exp+coachcal://expo-development-client/...`),
   which keeps the process arguments intact. (Source: docs.maestro.dev `launchApp` reference.)
2. **`${{ runner.temp }}` is not allowed in job-level `env:`** (only `github`, `inputs`,
   `matrix`, `needs`, `secrets`, `strategy`, `vars` contexts are). The first push failed in 0 s
   with "workflow file issue"; `actionlint` names the exact context rule. The env file variable
   moved to step-level `env:`, where the `runner` context is allowed.
3. The smoke scripts take `PG_BIN` as a directory (`"$PG_BIN/psql"`); the runner's client is at
   `/usr/bin`, so the job sets `PG_BIN: /usr/bin` (the scripts' homebrew default is macOS-only).
   `jq`, `curl` and `openssl` are preinstalled on `ubuntu-24.04`; the job guards `psql` and
   `uuidgen` with `command -v … ||` installs anyway.
4. The scan review's plus button is `ccstepper.increment`, a design-system Stepper testID inside
   the `scan.grams.<item.id>` wrapper — not a `scan.*` id. Renaming it would touch
   `apps/mobile/src/design/components/Stepper.tsx`, which is outside this unit's scope; the tap
   addresses the identifier, never a pixel, which is what the brief's rule protects. The golden
   response has exactly one item, so the identifier is unique on screen.
5. The RN screen markers are the raw strings, not the visually uppercased ones: SectionHeader
   applies `textTransform: uppercase`, but the accessibility tree carries "Today's insights" and
   "Goals & targets" — the evidence flows' uppercase markers ("TODAY'S INSIGHTS") are the Swift
   app's copy.
6. `apps/mobile/ios/` is generated by `expo prebuild` on the runner (the gitignore pattern
   `apps/*/ios/` keeps it out); nothing native is committed.
7. First JS load on a cold runner compiles the whole Metro bundle: the flows' first
   `extendedWaitUntil` allows 5 minutes; later flows reuse the warm Metro transform cache.
8. The integration job runs `npm test` before the smokes — the same order as the owner's gate —
   and it works because the Jest harness cleans every row it created, so `e2e-sync.sh` finds
   user 1 empty (its fixed opIds would otherwise answer `duplicate`).
