## 3. Deviations

1. **`search.escape.manual` opens the CustomFoodSheet, not ManualLogSheet.** The brief says "Manual
   opens the manual log sheet", but `ManualLogSheet` is row-driven: its kcal derives from the
   catalog row (`manualKcal(row.kcal, grams)`) and it has no blank entry point — opening it without
   a row would show a nameless sheet with a 0 kcal figure, which breaks the derived-kcal rule the
   brief freezes. The app's actual manual entry path is the custom-food sheet, so the escape lands
   there. The frame's freeform Name/Amount/Meal sheet belongs to the owner's segment follow-up
   (the Food/Exercise/Custom-food sheet is explicitly out of this unit). One-line swap if the owner
   wants another target.
2. **The Advanced fold collapses without blur.** The frame says "collapsed and blurred"; no blur
   package is installed and packages are frozen for this unit (rule 4). Collapsed-only, as the brief
   instructs; the fields keep their `custom.<field>Field` identifiers when unfolded.
3. **"From search" caption maps to `source === 'manual'`.** The detail payload has no `'search'`
   source. Every manual log in the app is created from the search flow (FoodSearchView is the only
   ManualLogSheet entry), so the search-logged row shows the frame's caption when it carries no
   confidence badge. Other sources (`scan`, `relog`, `cache`) show nothing extra — show what a row
   has, invent nothing.
4. **`diary.previousDay` / `diary.nextDay` already existed.** The brief says "RN does not yet. Add
   them" — both `testID`s and the disabled-next-on-today behavior were already on main
   (U-32). Nothing to add; tests already cover them.
5. **Exercise row kcal shows the bare figure (`300`), not `300 kcal`.** The frame shows the number
   only, in `--cc-text-2`; the unit moved to the new exercise header (`−300 kcal`, `EdSafeCollapse`d,
   `model.burnedKcal()` — a new model method summing the day's `kcalBurned`, null without rows).
6. **The add-food sheet's tile style and rail.** The five quick-action tiles stay the DS
   `QuickActionTile` (the frame's dashed tile style and canvas icons are design-side); the sheet
   chrome/grabber already come from DS `Sheet`.
7. **Water card and sheet show litres/glasses as today.** The frame's "1.25 of 2 L" litres copy is
   the Today unit's behavior change (U-76, TD-01); this unit only took the droplet tile and chip
   pattern (DY-07 is `derived`), so the glasses copy that the existing tests lock stays.

## 10. Stage A2, second addendum — the owner un-did two deviations

The owner's new goal ("every screen on Ember, the new frames included") promoted two deviations
into work and changed the delete confirmation's shape. Built on the same branch:

1. **The delete confirmation is the system action sheet** (`d-delete-*`): `ActionSheetIOS`
   (`title` "Delete <name>?", `message` "This removes <kcal> kcal from <meal>. You can undo for
   5 seconds." — the sheet keeps its word now that the undo exists; the no-kcal fallback keeps the
   old sentence), `options: ['Delete item', 'Cancel']`, destructive 0, cancel 1. The two stacked
   cards are gone; the tests spy `ActionSheetIOS.showActionSheetWithOptions` (with
   `mockImplementation` — a bare `spyOn` calls through and the native invariant fires) and drive
   the callback for both buttons. Its rendering belongs to stage B (no Simulator slot).
2. **The undo of a delete** (`d-deleted-*`): after the delete, a toast (`diary.toast.undo`,
   "<name> deleted" / "Removed from <meal>", DS `Toast` with an Undo chip) stays five seconds —
   the view owns the window (its own `setTimeout`; the DS Toast's own 4 s timer stays off because
   no `onDismiss` is passed). Inside the window `DiaryDayModel.undoDelete(item)` runs: the
   feature's new seam in `diarySnapshot.ts` (`findPendingTombstoneOp`, `cancelPendingOp`,
   `restoreRowsWithoutOp` — drizzle over the injected handle, one transaction, no new op) cancels
   the tombstone op and restores the mirror + detail rows exactly as the snapshot held them; if
   the sync has taken the op, the model re-records the entry the way a save does
   (`recordUpserts`, one new op). After the window the toast leaves and the delete is final.
3. **The saved state of an edit** (`d-saved-*`): after "Save changes", a toast
   (`diary.toast.undoEdit`, "Changes saved" / "<name> · <grams> g", Undo chip) stays five seconds;
   the undo inside the window restores the previous detail exactly through
   `DiaryDayModel.writeEntry(entry, detail)` (one batch, one op). The "Edited" label
   (`diary.editedChip.<id>`) shows on the edited row and persists: it is derived from the mirror
   row (`updatedAt > createdAt`), the only local update path of an existing entry being the edit
   sheet — see the deviation below about the brief's "store it on the entry's detail".
4. **The two ED-Safe captions stay listed**: `EdSafeAlternate` is on PR 39 (rn/u-72-scan-ember,
   not merged), and the owner said to build against it only once it is on main. The serving
   caption of a search row and the Advanced fold of the custom food sheet still read
   `useEdSafeMode()` (the two documented stays of §8).
