## 1. Leak fixes (the first thing this unit did)

All four PL-08 diary leaks are closed and tested both ways (figure/field absent under ED-Safe and
back with the mode off):

| Leak | File | How the policy stays in design |
|---|---|---|
| Food search rows | `FoodSearchView.tsx` | The kcal footnote is wrapped in `EdSafeCollapse`; under the mode the same slot shows the serving size (`${servingGrams} g`) or the basis string (`100g` / `serving`) when the row has no serving |
| Manual log kcal | `ManualLogSheet.tsx` | The `manual.kcal` row is wrapped in `EdSafeCollapse`; the note card ("No numbers needed.") appears only under the mode |
| Exercise kcal field | `ExerciseLogSheet.tsx` | The `exercise.kcalField` input is wrapped in `EdSafeCollapse`; the note "Activity and minutes only. Burned kcal is hidden." appears only under the mode |
| Custom food nutrition fields | `CustomFoodSheet.tsx` | Under the mode the kcal/protein/carbs/fat/fiber fields fold into an "Advanced" group, collapsed by default and unfolded by tap; with the mode off they render flat as today |

`grep -rnE "useEdSafeHidden\(|edSafeHidden\(|edSafeMode\(" apps/mobile/src/features/diary` prints
nothing at the pushed head. `DiaryDayView.tsx` and `AddFoodSheet.tsx` no longer call
`useEdSafeHidden()`; their kcal surfaces (summary card, section kcal, exercise header and row kcal,
saved-meals rail kcal) wrap in `EdSafeCollapse`.

**ED-Safe-only notes and captions read `useEdSafeMode()`.** The design system has no component that
renders content only while the mode is on (`EdSafeNote` is the second batch), and the features may
not call the three banned names. I used the sanctioned read (standing-order rule 20, sentence 2 —
"a feature may read the mode to show a control's state") for: the manual/exercise/custom note cards,
the search row's serving-size caption, and the exercise row's accessibility label (same strings as
before — kcal in the label only while the figure is visible). All of these swap to `EdSafeNote` /
the second-batch components in stage A2; the reads then leave the feature.

## 3. Deviations

1. **`search.escape.manual` opens the CustomFoodSheet, not ManualLogSheet.** The brief says "Manual
   opens the manual log sheet", but `ManualLogSheet` is row-driven: its kcal derives from the
   catalog row (`manualKcal(row.kcal, grams)`) and it has no blank entry point — opening it without
   a row would show a nameless sheet with a 0 kcal figure, which breaks the derived-kcal rule the
   brief freezes. The app's actual manual entry path is the custom-food sheet, so the escape lands
   there. The frame's freeform Name/Amount/Meal sheet belongs to the owner's segment follow-up
   (the Food/Exercise/Custom-food sheet is explicitly out of this unit). One-line swap if the owner
   wants another target.
2. **The Advanced fold collapses without blur.** The frame says "collapsed and blurred"; no blur
   package is installed and packages are frozen for this unit (rule 4). Collapsed-only, as the brief
   instructs; the fields keep their `custom.<field>Field` identifiers when unfolded.
3. **"From search" caption maps to `source === 'manual'`.** The detail payload has no `'search'`
   source. Every manual log in the app is created from the search flow (FoodSearchView is the only
   ManualLogSheet entry), so the search-logged row shows the frame's caption when it carries no
   confidence badge. Other sources (`scan`, `relog`, `cache`) show nothing extra — show what a row
   has, invent nothing.
4. **`diary.previousDay` / `diary.nextDay` already existed.** The brief says "RN does not yet. Add
   them" — both `testID`s and the disabled-next-on-today behavior were already on main
   (U-32). Nothing to add; tests already cover them.
5. **Exercise row kcal shows the bare figure (`300`), not `300 kcal`.** The frame shows the number
   only, in `--cc-text-2`; the unit moved to the new exercise header (`−300 kcal`, `EdSafeCollapse`d,
   `model.burnedKcal()` — a new model method summing the day's `kcalBurned`, null without rows).
6. **The add-food sheet's tile style and rail.** The five quick-action tiles stay the DS
   `QuickActionTile` (the frame's dashed tile style and canvas icons are design-side); the sheet
   chrome/grabber already come from DS `Sheet`.
7. **Water card and sheet show litres/glasses as today.** The frame's "1.25 of 2 L" litres copy is
   the Today unit's behavior change (U-76, TD-01); this unit only took the droplet tile and chip
   pattern (DY-07 is `derived`), so the glasses copy that the existing tests lock stays.

wrapper is untouched (DiaryRoute.test pins it) and now also sets the native detents
(`sheetAllowedDetents: [0.5, 1]` via `navigation.setOptions` — the route file, as the brief says).
