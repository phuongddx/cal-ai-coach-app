# Infrastructure

## CI — GitHub Actions

`.github/workflows/rn-ci.yml` is the only workflow (name "RN CI", single job `test`, "Typecheck, Jest
and parity gate"):

- Runner `ubuntu-24.04`, Node 24 with the npm cache, 30-minute timeout, one run per ref
  (`concurrency` cancels the older run).
- Triggers: pull requests, pushes to `main` and manual dispatch; a change that touches only
  `supabase/**` or `deno.lock` is skipped.
- Steps: `npm ci`, `npm run typecheck`, `npm test`, `npm run parity:check`.
- What it proves: every workspace type-checks (including Expo Router typed routes, regenerated by
  `scripts/rn/gen-typed-routes.mjs`), the Jest suites pass, and the parity table and its checks hold.
  The SQL suites of `apps/api` print `[sql-skip]` there because no PostgreSQL service is configured.
- What it does not do: build the app, run a Simulator or the evidence harness, run the legacy Deno
  tests, deploy anything.

The SwiftUI workflows (`ci.yml`, `release-ipa.yml`) and the Xcode Cloud hook (`ci_scripts/`) were
removed in U-70; the tag `archive/swiftui-final` holds them.

## Local gates

- `bash scripts/rn/gate.sh` runs the same three steps as CI (`npm test`, `npm run typecheck`,
  `npm run parity:check`) with a lock, so only one gate runs on the machine at a time; `GATE_STEPS`
  picks a subset.
- `bash scripts/rn/start-api.sh` starts a throwaway PostgreSQL 17 on port 5433 and the API on 8787
  (roles `coachcal_owner` and `coachcal_api`, migrations applied, `OTP_SENDER=log`, random secrets
  per run), writes an env file named after the checkout, and `bash scripts/rn/start-api.sh stop`
  removes both. The API SQL suites read that env file.
- `scripts/rn/smoke-auth.sh`, `smoke-scan.sh`, `e2e-sync.sh` run against that API.

## Native build and evidence (macOS, Xcode)

- The app is built as a development client with Continuous Native Generation: `expo prebuild`
  generates `apps/mobile/ios/` (git-ignored). `docs/rn-migration/build-recipe.md` says what builds on
  this machine and the pitfalls; `scripts/rn/native-slot.sh` guards the single build slot (clean
  tree, at least 6 GB free).
- `bash scripts/rn/check-native-modules.sh` says which native module the code needs and a built app
  lacks.
- Evidence comes from one Simulator (`iPhone 17 Pro`, iOS 26.4, found by name with
  `scripts/rn/sim-udid.sh`) driven by `axe` and `xcrun simctl`: `bash scripts/rn/evidence/run-all.sh`
  writes screenshots and transcripts under `docs/rn-migration/evidence/`.
- `node scripts/rn/check-artifact-compliance.mjs <CoachCal.app>` checks the release surface of a
  built app (entitlements, Info.plist strings, privacy manifest, no secrets inside).

## Backend deployment kit (not yet run on a server)

`apps/api/deploy/` + `apps/api/Dockerfile`: Docker Compose with `postgres:17`, a one-shot `migrate`
service, the `api` service (image `coachcal-api`, Node 24, runs the TypeScript through `tsx`) and
`caddy:2` for automatic HTTPS on `$DOMAIN`; only Caddy publishes ports. `initdb/01-roles.sh` creates
the two roles, `backup.sh` does `pg_dump` backup, restore and verify. The steps are in
`docs/rn-migration/deploy-vps.md` (written for the owner to run; nothing was deployed to a real VPS).
Environment names and meanings: `apps/api/.env.example` (no values). The mobile app reads
`EXPO_PUBLIC_API_URL` (`apps/mobile/.env.example`).

## Legacy Supabase stack (not developed further)

- `supabase/config.toml`: project `cal-ai-coach-app`, Postgres major 17, API
  `http://127.0.0.1:54321`, DB port `54322`, edge runtime Deno 2.
  `[functions.rc-webhook] verify_jwt=false`.
- Serve functions: `supabase functions serve --env-file supabase/functions/.env`; hosted secrets:
  `supabase secrets set NAME=value`; edge tests: `cd supabase/functions && deno task test`
  (sequential, local-stack env required). The root `.env.example` lists its environment names.
- Not part of CI. It goes when the hosted Hono backend runs.

## Signing & env injection

- Bundle id `com.nextlabs.coachcal`, scheme `coachcal`, App Group `group.com.nextlabs.coachcal`
  (`apps/mobile/app.config.ts`, `apps/mobile/plugins/with-coachcal-entitlements.js`).
- The Swift era used manual signing (team `K2TYLYAWMK`); no signing asset, App Store Connect record
  or EAS account is touched by the React Native program. Never commit signing material (`.gitignore`
  ignores `*.p8`, `*.p12`, `*.mobileprovision`, …).

- A tested production deployment of the Hono backend; EAS builds; App Store submission from the
